= Operating Applications on OpenShift 5: Platform Engineering, AI & GitOps
:navtitle: Lab Overview

Work through the responsibilities of a platform engineer: establish an application baseline, understand GitOps, apply tenant and resource controls, investigate an incident, and deliver a verified fix.

Module 1 is *Mission National Parks*: a 25-minute, UI-first OpenShift 5 discovery exercise using the National Parks application from the 5.0 Tutorials guide. You will experience the redesigned console, connect a real Route to the new ingress defaults, scale the frontend, and independently verify OpenShift Lightspeed's MCP findings.

The workshop is designed for up to 30 participants on a shared OpenShift cluster. Each participant uses an assigned identity and application namespace.

== What You Will Do

* Identify the frontend, backend, and database in `national-parks-app`.
* Explore the updated OpenShift 5 Project Felt console and verify the actual platform version.
* Open the populated map and inspect the three workloads in the OpenShift Topology view.
* Trace the Route → Service → EndpointSlice → ready pod path, and identify the effective serving HAProxy version.
* Scale the frontend from one to two replicas in the UI, observe endpoint readiness, and restore the baseline.
* Challenge Lightspeed to inspect the live resources using its built-in MCP reads, then verify an answer independently.
* Distinguish new OpenShift 5 capabilities from long-established OpenShift foundations.
* Inspect workload health/logs and complete a short readiness card.
* Continue into the GitOps, access control, resource management, and incident investigation drafts using the same application.

The guide distinguishes documented OpenShift 5 changes from existing foundations such as Deployments, Routes, GitOps, RBAC, and NetworkPolicy.

== Before You Start

This workshop is intended for intermediate platform engineers and site reliability engineers. You should be comfortable with pods, Deployments, namespaces, basic RBAC, and running `oc` commands. Later exercises also require basic Git operations.

Your application namespace and console username are `{lab_user}`. The terminal can authenticate as the corresponding Showroom service account; its hosting namespace can differ from the application namespace. Keep credentials out of AI prompts and notes.

Module 1 uses a healthy, pre-provisioned application. Database initialization and image builds are instructor preparation, outside the timed lab. The module includes a reversible frontend scale operation, six observable checkpoints, and **no injected incident**. The deliberate break/fix story belongs in Module 4.

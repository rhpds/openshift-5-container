= Operating Applications on OpenShift 5: Platform Engineering, AI & GitOps
:navtitle: Lab Overview

Work through the responsibilities of a platform engineer: establish an application baseline, understand GitOps, apply tenant and resource controls, investigate an incident, and deliver a verified fix.

Module 1 is *Mission National Parks*: a 25–30-minute console-first workshop (28-minute guided path). Students deploy the frontend, Python API and working MongoDB 8, encounter an incorrect MongoDB Service target port. Lightspeed 2.0 helps diagnose the connection failure; students repair one Service field, load data and verify the map.

The workshop is designed for up to 30 participants on a shared OpenShift cluster. Each participant uses an assigned identity and application namespace.

== What You Will Do

* Select your existing `{user}-demo` project, then explore the updated OpenShift 5 Project Felt console. Do not create a namespace.
* Deploy `parksmap` from a container image using the native console's Quick create flow.
* Import the Python `nationalparks` API from Git and observe its build in Topology.
* Create a MongoDB Secret with your own passwords in your assigned project.
* Import a working MongoDB 8 Deployment, bootstrap ConfigMap and internal Service through the console YAML editor.
* Connect the backend to your Secret and observe the deliberately incorrect MongoDB Service target port.
* Use Lightspeed to investigate the MongoDB connection failure, repair its Service port and load park data.
* Complete a workload-readiness card and continue into GitOps onboarding.

This module deliberately distinguishes new OpenShift 5 appearance/MCP capabilities from long-standing Deployments, Routes, Builds, YAML import and GitOps.

*Planned full workshop: approximately 2 hours 55 minutes (pending live rehearsal of AgenticRuns and Modules 4–5).* Module 1 targets 28 guided minutes, allowing up to 30 minutes in a preflighted student environment. Registry pulls, Git builds, student Secret creation, discovery RBAC, the deliberate MongoDB Service port fault, Lightspeed 2.0 reads and the console repair must be rehearsed to meet this timing. The former scaling and ingress-controller inspection exercises are outside this timebox. Module 2 now deploys an independent, full National Parks stack to each student's -gitops namespace with automatic reconciliation; Module 1 remains unchanged in -demo. Module 3 uses a deliberately incorrect GitOps-managed ParksMap readiness port to demonstrate why Synced does not imply Healthy, followed by evidence-backed Lightspeed and optional analysis-only AgenticRun investigation; it ends with both stacks healthy again.

== Before You Start

This workshop is intended for intermediate platform engineers and site reliability engineers. You should be comfortable with pods, Deployments, namespaces, basic RBAC, and running `oc` commands. Later exercises also require basic Git operations.

Sign in as `{user}` in both the console and terminal; run `oc whoami` and verify it returns `{user}` before patching anything in `{user}-demo`. Never use the default Showroom ServiceAccount for workshop commands.

Module 1 starts in `{user}-demo`. Students deploy the frontend, Python backend and working MongoDB 8, investigate the preconfigured MongoDB port fault with Lightspeed, repair it in the console, then load park data once.

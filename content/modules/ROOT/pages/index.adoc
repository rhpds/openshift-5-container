= Operating Applications on OpenShift 5: Platform Engineering, AI & GitOps
:navtitle: Lab Overview

Work through the responsibilities of a platform engineer: establish an application baseline, understand GitOps, apply tenant and resource controls, investigate an incident, and deliver a verified fix.

Module 1 is *Mission National Parks*: a 50-minute, native-console deployment and recovery mission. Students create the frontend from a container image, import the Python API from Git, create their own MongoDB Secret, and deploy an intentionally outdated MongoDB image. They use *OpenShift Lightspeed 2.0 Troubleshooting* and its built-in Kubernetes MCP read tools to diagnose the incompatibility, then apply a reviewed image-only repair themselves through the console before bringing the populated map online.

The workshop is designed for up to 30 participants on a shared OpenShift cluster. Each participant uses an assigned identity and application namespace.

== What You Will Do

* Select your existing `{user}-demo` project, then explore the updated OpenShift 5 Project Felt console. Do not create a namespace.
* Deploy `parksmap` from a container image using the native console's Quick create flow.
* Import the Python `nationalparks` API from Git and observe its build in Topology.
* Create a MongoDB Secret with your own passwords in your assigned project.
* Import a prepared MongoDB ConfigMap, Deployment and internal Service through the console YAML editor.
* Connect the backend to your Secret and observe the intentional driver/database version incompatibility.
* Diagnose the failure through Lightspeed 2.0 live MCP reads, review its evidence, apply the MongoDB image fix manually in the console, then load sample data and see the map come to life.
* Complete a workload-readiness card and continue into GitOps onboarding.

This module deliberately distinguishes new OpenShift 5 appearance/MCP capabilities from long-standing Deployments, Routes, Builds, YAML import and GitOps.

== Before You Start

This workshop is intended for intermediate platform engineers and site reliability engineers. You should be comfortable with pods, Deployments, namespaces, basic RBAC, and running `oc` commands. Later exercises also require basic Git operations.

Your console username is `{user}`; the application project for Module 1 is `{user}-demo`. The terminal can authenticate as the corresponding Showroom service account, which may have different permissions. Keep credentials out of AI prompts and notes.

Module 1 starts by selecting the existing `{user}-demo` project. Students create the frontend and build the backend in the console, create the MongoDB Secret, import the deliberately incompatible database image, then use Lightspeed 2.0 MCP reads to diagnose the failure and perform a manual console Service repair before populating disposable park data once. The instructor confirms Secret creation, discovery RBAC, registry/builder access, live MCP reads, and Deployment edit permissions beforehand. Module 4 has a separate incident-investigation exercise.

= Operating Applications on OpenShift 5: Platform Engineering, AI & GitOps
:navtitle: Lab Overview

You are a platform engineer on a team that runs a shared OpenShift cluster. Multiple application teams depend on it. Your job is to keep things running — onboarding new applications safely, enforcing fair resource use, and resolving production incidents before they escalate.

This lab runs that scenario end to end. You will onboard an application through GitOps, lock down namespace access and network policy, manage resource contention across thirty concurrent users, investigate an injected production incident using OpenShift Lightspeed alongside real metrics, logs, and traces, and push your validated fix back through GitOps.

Everything happens on a live {ocp_version} shared cluster. Your namespace is yours alone — isolated from the other 29 participants on the same cluster.

== What You Will Learn

* Configure application onboarding through GitOps (ArgoCD), including namespace, RBAC, and NetworkPolicy creation
* Verify tenant isolation holds between student namespaces after onboarding
* Manage resource contention across shared workloads using ResourceQuotas, LimitRanges, and PriorityClasses
* Analyze workload resource usage on a shared cluster and right-size deployments accordingly
* Troubleshoot an injected production incident using OpenShift Lightspeed together with metrics, logs, and traces
* Verify OpenShift Lightspeed's recommendations against real cluster data before acting on them
* Implement a validated fix declaratively through GitOps and confirm recovery
* Monitor rollout health and ArgoCD sync status while performing a rolling update

== Before You Start

This lab is designed for intermediate-level platform engineers and site reliability engineers. You should be comfortable with:

* Core OpenShift/Kubernetes concepts — pods, deployments, namespaces, and basic RBAC
* Basic Git usage — cloning a repository, committing changes, and pushing to a remote

No prerequisite check runs automatically. If any of those concepts are unfamiliar, the https://docs.redhat.com/en/documentation/openshift_container_platform/[OpenShift documentation] is a good place to close the gap before you begin.

= Operating Applications on OpenShift 5: Platform Engineering, AI & GitOps
:navtitle: Lab Overview

LB1858 is a per-student lab for platform teams running applications on Red Hat OpenShift Container Platform 5 with Red Hat OpenShift GitOps (Argo CD). Before ordering a student seat, the instructor must provision the shared cluster using `lb1858-ocp5-container-mngmt-cluster` and confirm it is running. Student orders attach to that cluster.

[cols="2,4",options="header"]
|===
| Platform responsibility | Evidence you will collect
| GitOps onboarding | A student Gitea commit, the matching Argo CD revision and the updated live ConfigMap.
| Multitenancy | An external reference tenant's API read changes from denied to allowed and back. Its network connection times out under your policy while your local client receives HTTP 200.
| Workload management | CPU and memory measurements, an admission decision under shared quota, and the verified result of your sizing decision.
| Incident investigation | A pod-specific metric, log observation and failed readiness event explain the mismatch between port 18080 and port 8080.
| Application lifecycle | The bad image revision and pull event, followed by the Git repair, matching synced revision, updated Ready replicas and HTTP 200.
|===

Module 1 is *Mission National Parks*: a 25–30-minute console-first workshop (28-minute guided path). Students deploy the frontend, Python API and working MongoDB 8, encounter an incorrect MongoDB Service target port. Lightspeed 2.0.1 diagnoses the connection failure and, with student approval through MCP, repairs one Service field. Students independently verify the change, load data and confirm the map; a manual fallback remains available.

The workshop is designed for up to 30 participants on a shared OpenShift cluster. Each participant uses an assigned identity and application namespace.

== What You Will Do

* Select your existing `{user}-demo` project, then explore the updated OpenShift 5 Project Felt console. Do not create a namespace.
* Deploy `parksmap` from a container image using the native console's Quick create flow.
* Import the Python `nationalparks` API from Git and observe its build in Topology.
* Create a MongoDB Secret with your own passwords in your assigned project.
* Import a working MongoDB 8 Deployment, bootstrap ConfigMap and internal Service through the console YAML editor.
* Connect the backend to your Secret and observe the deliberately incorrect MongoDB Service target port.
* Use Lightspeed Troubleshooting to diagnose the MongoDB connection failure, inspect and approve an MCP Service-port repair, and verify the result before loading park data.
* Complete a workload-readiness card and continue into GitOps onboarding.

This module deliberately distinguishes new OpenShift 5 appearance/MCP capabilities from long-standing Deployments, Routes, Builds, YAML import and GitOps.

== Before You Start

This workshop supports Kubernetes/OpenShift beginners through intermediate platform engineers and site reliability engineers; instructor-provided application baselines reduce setup time. You should be comfortable with pods, Deployments, namespaces, basic RBAC, and running `oc` commands. Later exercises also require basic Git operations.

The console, Gitea and Terminal have separate sessions. After reconnecting to Showroom, check +oc whoami+ in the Terminal you will use. Sign in as `{user}` in both the console and terminal. Never use the default Showroom ServiceAccount for workshop commands. In the Showroom *Terminal* tab, paste this block and confirm the last line prints `{user}` before changing anything in `{user}-demo`:

[source,bash,subs="attributes+",role=execute]
----
export KUBECONFIG="$HOME/.kube/lb1858-{user}.config"
mkdir -p "$HOME/.kube" &&
oc login --server={openshift_api_url} --username={user} --password='{password}' --insecure-skip-tls-verify &&
oc whoami | grep -Fx -- '{user}'
----

Module 1 starts in `{user}-demo`. Students deploy the frontend, Python backend and working MongoDB 8, investigate the preconfigured MongoDB port fault with Lightspeed, approve the scoped MCP Service repair (or document a manual fallback), then load park data once.

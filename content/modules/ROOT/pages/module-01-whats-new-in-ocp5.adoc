= Mission National Parks: Deploy with the OpenShift 5 Console
:navtitle: Mission National Parks
:page-toclevels: 2
:experimental:

Deploy the National Parks frontend, Python API and MongoDB 8 in your existing workshop project. Then deliberately break one Service selector, use Lightspeed to find the problem and repair it in the OpenShift console. Leave the existing Argo CD, Gitea and workshop workloads alone.

This is a *50-minute, console-first workshop* using *OpenShift Lightspeed 2.0*. Lightspeed investigates; you apply the repair.

[cols="1,1,1,1,1,1,1,1",options="header"]
|===
| 0–2 | 2–11 | 11–17 | 17–27 | 27–33 | 33–43 | 43–48 | 48–50 min
| Select project | Frontend + discovery permissions | Python API | MongoDB 8 + test data + break Service | Diagnose with Lightspeed | Repair Service in console | Verify map | Sign-off
|===

oc get deployment parksmap -n {user}-demo \
  -o jsonpath='{.spec.template.spec.serviceAccountName}{"\n"}'
----
+
Expected:
+
[source,text]
----
parksmap-discovery
----
+
If the output is blank or says `default`, the Deployment is **not fixed**. Check that `oc whoami` returns `{user}`, then repeat the patch. A RoleBinding alone does not make the Pod use this identity. **Do not continue until this check passes.**

== Mission 3: Connect MongoDB and create the failure (10 minutes)

Deploy a *working* MongoDB 8 database, load park data, then break the backend Service on purpose.

. In project `{user}-demo`, open *Workloads* -> *Secrets* -> *Create* -> *Key/value secret*. Name it `nationalparks-mongodb-parameters`. Add these five keys:

[cols="2,3",options="header"]
|===
| Key | Value
| `DATABASE_SERVICE_NAME` | `mongodb-nationalparks`
| `MONGODB_USER` | `mongodb`
| `MONGODB_DATABASE` | `mongodb`
| `MONGODB_PASSWORD` | Your own strong password (at least 16 characters)
| `MONGODB_ADMIN_PASSWORD` | A *different* strong password (at least 16 characters)
|===

+
image::module01-s09a-secret-create-menu.png[Create a key/value Secret, width=800]
+
[IMPORTANT]
====
Do not copy passwords from screenshots or paste them into Lightspeed. If the Secret already exists, ask your instructor before reusing it.
====

. Select *Create*. Then select *Quick create* (`+`) -> *Import YAML*. Copy and create the three resources below: a bootstrap ConfigMap, MongoDB Deployment and internal Service.
+
[source,yaml]
----
include::example$module01-mongodb.yaml[]
----
. Open *Workloads* -> *Deployments* -> `nationalparks` -> *YAML* -> *Edit*. Add this to the existing application container, alongside `image` and `ports`:
+
[source,yaml]
----
envFrom:
  - secretRef:
      name: nationalparks-mongodb-parameters
----
. Save. Wait for `mongodb-nationalparks` and `nationalparks` to be Ready.
. Open https://national-parks-app-{user}-demo.{openshift_cluster_ingress_domain}/ws/data/load[Load National Parks data,window=_blank] **once** to seed the disposable database. Then open https://national-parks-app-{user}-demo.{openshift_cluster_ingress_domain}/ws/data/all[View National Parks data,window=_blank] and confirm it contains park records. **Do not repeat the load request.**
. **Create the fault:** In *Networking* -> *Services*, open the *Python backend Service* (`national-parks-app` or your actual backend name), **not** `mongodb-nationalparks`. Choose *YAML* -> *Edit*. Under `spec.selector`, find the existing `app` value and change **only that value** to:
+
[source,yaml]
----
app: intentionally-broken-backend
----
+
Keep the remaining selector keys and all other fields unchanged. Save.
. Refresh https://national-parks-app-{user}-demo.{openshift_cluster_ingress_domain}/ws/data/all[National Parks data,window=_blank]. It should now fail because the Service no longer selects its Pods. The Pods can still be *Running*.

*Checkpoint 3 — mandatory:* Before opening Lightspeed, confirm that the backend Service has **no ready endpoints** but the backend Pod is Running. In the Showroom terminal:
+
[source,bash,subs="attributes+"]
----
oc get svc national-parks-app -n {user}-demo -o jsonpath='{.spec.selector}{"\n"}'
oc get endpointslice -n {user}-demo -l kubernetes.io/service-name=national-parks-app
----
+
The selector must contain `app=intentionally-broken-backend`, and the EndpointSlice must show no ready backend addresses. If your backend Service has a different name, use that name in both commands. **Do not start Lightspeed until this deliberate failure is present.**

== Mission 4: Find the problem with Lightspeed (6 minutes)

. Open *OpenShift Lightspeed* -> *Troubleshooting*.
+
image::module01-s09k-lightspeed-mode.png[Select Lightspeed Troubleshooting, width=850]
. Paste this prompt:
+
[source,text,subs="attributes+"]
----
My National Parks application stopped working.

Use live Kubernetes tools to check the Pods, Services and Routes
in namespace {user}-demo. Find the cause and explain how to fix it.

Do not read Secrets or change anything.
----
. Review the answer. If approval is requested, approve *only* read operations in your namespace. Lightspeed should find this mismatch:
+
[source,yaml]
----
# Service: national-parks-app (example)
selector:
  app: intentionally-broken-backend
  deployment: national-parks-app

# Backend Pod labels
app: national-parks-app
deployment: national-parks-app
----
+
The Service has **no endpoints**, even though the backend Pod is *Running*. This selector mismatch was correctly diagnosed in a previous live Lightspeed 2.0 rehearsal with Claude Sonnet 4.6. If Lightspeed instead reports missing ParksMap RBAC, repeat Checkpoint 1; if it reports matching selectors, repeat Checkpoint 3.

[TIP]
====
*AI check:* Lightspeed may suggest more than one fix. Confirm the selector mismatch in the console before applying changes.
====

*Checkpoint 4:* You can explain why the backend Pod can be Ready while its Route is unavailable.

== Mission 5: Repair the Service (5 minutes)

. In *Networking* -> *Services*, open the Python backend Service (`nationalparks` or `national-parks-app`) -> *YAML* -> *Edit*.
. Under `spec.selector`, change **only** the `app` value back to the actual value on your backend Pod (typically `national-parks-app`):
+
[source,yaml]
----
selector:
  app: national-parks-app
  deployment: national-parks-app
----
+
Keep any other existing selector keys unchanged.
. Select *Save*. Check the Service has backend endpoints again. Open https://national-parks-app-{user}-demo.{openshift_cluster_ingress_domain}/ws/data/all[National Parks data,window=_blank] to verify the Route works. No Pod restart is needed.

*Checkpoint 5:* You fixed one Service selector value without touching the database or restarting Pods.

. Open https://parksmap-{user}-demo.{openshift_cluster_ingress_domain}/ws/backends/list[ParksMap backend list,window=_blank]. It should include `nationalparks`, not `[]`.
. Open https://parksmap-{user}-demo.{openshift_cluster_ingress_domain}/[ParksMap,window=_blank]. Check that the *National Parks (PY)* layer displays park markers.

== Troubleshooting quick reference

[cols="2,3",options="header"]
|===
| Symptom | Check
| Can't see `{user}-demo` | Sign in with your student account; ask the instructor rather than creating another project.
| Python build fails | Open *Builds* -> *Logs* and inspect the error.
| MongoDB does not start | Check the Secret's name and keys, ConfigMap and Pod events; don't share passwords.
| Backend Route fails after Mission 3 | Expected. The Python backend Service selector deliberately matches no Pods.
| Lightspeed cannot inspect resources | Check the exact namespace in the prompt and student read permissions.
| Backend Route still fails after Mission 5 | Compare `spec.selector` on the backend Service with the backend Pod's labels.
| API returns data but map is blank | Check `parksmap-discovery` ServiceAccount and `type=parksmap-backend` on backend Service and Route.
|===

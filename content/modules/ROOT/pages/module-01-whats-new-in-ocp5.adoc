= Mission National Parks: Deploy with the OpenShift 5 Console
:navtitle: Mission National Parks
:page-toclevels: 2
:experimental:

The National Parks application has not been deployed to your workshop project yet. Your project may already contain Showroom, GitOps or other workshop services; leave those resources alone. As the platform engineer, you will deploy the frontend, build the Python API from Git and create your own database Secret. The supplied MongoDB Deployment has a *deliberately outdated image*: you will investigate the resulting failure, then use OpenShift Lightspeed and its built-in Kubernetes MCP integration to replace the image with a compatible version. Finally, you will load real park data and recover the map.

This is a *45-minute, console-first deployment and recovery mission*. Image deployment, Git import, Secrets, Routes, Services and the YAML editor are established OpenShift capabilities; the updated Project Felt interface and live MCP-assisted troubleshooting, approval and remediation are the OpenShift 5 experiences in this mission.

|===

== Mission 3: Create your Secret and deploy the broken database (10 minutes)

MongoDB and your Python backend both need database connection settings. You'll create those settings as a *Secret in your own project*, then deploy MongoDB and connect the backend. The supplied database image is *intentionally incompatible* with the Python driver: do not fix it yet! The prepared manifest does *not* create the Secret. Never paste password values into a lab guide, screenshot or AI chat.

. In the OpenShift console, confirm the project selector reads **`{user}-demo`**. Open *Workloads* -> *Secrets* and choose *Create* -> *Key/value secret*. If a Secret named `nationalparks-mongodb-parameters` already exists from an earlier attempt, **do not overwrite it**; confirm the name and skip to the MongoDB import step below. Ask your instructor if you are unsure whether it is safe to reuse.
. For *Secret name*, enter **`nationalparks-mongodb-parameters`**. Add the following **five key/value pairs**, using *Add key/value* for each additional entry:
+
[cols="2,3",options="header"]
|===
| Key | Value
| `DATABASE_SERVICE_NAME` | `mongodb-nationalparks`
| `MONGODB_USER` | `mongodb`
| `MONGODB_DATABASE` | `mongodb`
| `MONGODB_PASSWORD` | Choose your own unique password (at least 16 letters or digits).
| `MONGODB_ADMIN_PASSWORD` | Choose a **different** unique password (at least 16 letters or digits).
|===
. Select *Create*. Confirm that **`nationalparks-mongodb-parameters`** appears in the Secrets list in `{user}-demo`. You only need to verify its name; do not display or share the saved credentials. If you cannot create a Secret, stop and ask the instructor to check your project permissions. Do not create it in another namespace.
. In the console, select *Quick create* (`+`) -> *Import YAML* (sometimes labelled *YAML* or *Create from YAML*).
. Copy the following prepared *three-resource* manifest into the editor. It creates a small bootstrap ConfigMap, a MongoDB Deployment and an internal Service, but no public Route. MongoDB reads credentials from *the Secret you just created*. The ConfigMap contains only initialization code, never passwords. Leave the intentionally old MongoDB image unchanged for now.
+
[source,yaml]
----
include::example$module01-mongodb.yaml[]
----
+
image::module01-s04a-mongodb-yaml-editor.png[Earlier OpenShift YAML import example; the current manifest also creates a bootstrap ConfigMap, width=900]

. Review all three resources: `ConfigMap/mongodb-nationalparks-bootstrap`, `Deployment/mongodb-nationalparks` and `Service/mongodb-nationalparks`. Select *Create*.
+
image::module01-s04b-mongodb-created.png[Earlier confirmation screen showing two resources; the current import must create three, width=900]

. Open menu:Workloads[Deployments] -> `nationalparks` -> *YAML*. In its existing application container, add the following field under that container's properties (preserve its existing `image`, `ports` and other fields):
+
[source,yaml]
----
envFrom:
  - secretRef:
      name: nationalparks-mongodb-parameters
----
. Save the Deployment change. This starts a new backend rollout using the same database Secret as MongoDB. If the new Pod reports `secret "nationalparks-mongodb-parameters" not found`, recheck the Secret's name and project under *Workloads* -> *Secrets*. You do not need to delete or recreate the Deployment; OpenShift will retry when the Secret exists.
. Wait for the MongoDB and `nationalparks` Pods to start. Under *Networking* -> *Services*, confirm that *`mongodb-nationalparks`* has an internal ClusterIP Service but *no external Route*. Do not confuse this with the existing *`nationalparks`* Service, which exposes the Python backend internally on port `8080`.
. Open the MongoDB Deployment's *YAML* tab and find the container image field. It should intentionally show:
+
[source,text]
----
registry.redhat.io/rhmap47/mongodb
----
. Open the `nationalparks` Route's URL with `/ws/data/all` appended. It should fail or time out. *Do not call `/ws/data/load` while the database is broken.* A MongoDB Pod can be Ready because its TCP probe checks only that port `27017` is listening, not whether the Python driver is compatible.

[WARNING]
====
This is a *controlled failure for a disposable lab only*. The old MongoDB image is version 3.2.10, while the application uses PyMongo 4.18.1 (which requires MongoDB 4.4 or later). Never perform a direct major-version swap on an existing or persistent MongoDB dataset. Each new workshop Pod uses empty temporary storage. This is not a production database or an in-place migration procedure.
====

*Checkpoint 3:* You created `nationalparks-mongodb-parameters` in your own project, imported the three resources, and identified the deliberately broken `registry.redhat.io/rhmap47/mongodb` image. No password was shared and the database is internal. An empty or failing park-data endpoint is *expected* for now.

== Mission 4: Diagnose the failure with Lightspeed MCP (6 minutes)

. Open *OpenShift Lightspeed* using the OpenShift console's chat icon.
. Send this investigation prompt. Lightspeed should use live MCP tools to inspect the Deployments and read the MongoDB and Python Pod logs. If it cannot call the tools, do not treat a confident-sounding explanation as proof.
+
[source,text,subs="attributes+"]
----
My National Parks map cannot retrieve its park data.
Use live Kubernetes MCP tools only in namespace {user}-demo.
Inspect Deployments nationalparks and mongodb-nationalparks,
their Pod status, recent logs and events. Identify the MongoDB
server version and explain why the Python driver's connection fails.
Show the tool-result evidence. Do not read Secrets or change anything.
----
. Compare the explanation with the actual logs using *Workloads* -> *Pods* -> *Logs*. The MongoDB log should report version `3.2.10` and `cannot translate opcode 2013`. The National Parks backend uses PyMongo `4.18.1`; its `/ws/data/all` endpoint cannot communicate successfully with that MongoDB version.
. Ask Lightspeed whether the built-in MCP tool *`resources_create_or_update`* is available to your session. This is the tool that can apply a revised Kubernetes Deployment. A tool named `resources_scale` is *not* required for this task.

*Checkpoint 4:* You have log evidence of a *driver/server version incompatibility*, not a missing Secret or DNS failure. You know whether your session has the required live MCP update tool.

== Mission 5: Approve an MCP-driven MongoDB image fix (10 minutes)

OpenShift Lightspeed 1.1 supports write-capable built-in Kubernetes MCP tools with human approval before updates. Your instructor must have verified *`resources_create_or_update`* and namespace-scoped permissions under a **student account**. You do not need to install a separate MCP server. See https://docs.redhat.com/en/documentation/red_hat_openshift_lightspeed/1.0/html/release_notes/ols-release-notes[Red Hat OpenShift Lightspeed 1.1 release notes].

The approved recovery image is the MongoDB Community Server `8.0.32` UBI 9 image. The YAML you imported in Mission 3 already includes initialization settings for *both* image families; the *only requested Deployment modification* is the `mongodb` container's `image` field. Do not recreate your Secret, change the Service, or delete the Deployment.

. Send the following prompt to OpenShift Lightspeed. *The first step is to propose the exact change; wait for the approval UI before applying it.*
+
[source,text,subs="attributes+"]
----
Use resources_get to inspect Deployment mongodb-nationalparks in
namespace {user}-demo. The root cause is its MongoDB 3.2 image.

Use the built-in Kubernetes MCP resources_create_or_update tool to
replace ONLY the image of container "mongodb" with this approved tag:
quay.io/mongodb/mongodb-community-server:8.0.32-ubi9-slim

Preserve all other Deployment fields, existing env/envFrom Secret
references, ConfigMap bootstrap volume, replica count, labels,
ports and Service configuration. Fetch the complete Deployment,
edit its image field and submit the complete desired-state manifest.
Show the before/after image and ask for approval before execution.
Do not read or change Secrets, delete anything or touch other projects.
If the write tool is unavailable, say so; do not claim a fix occurred.
----
. In the approval dialog, inspect the proposed change. Confirm the namespace is exactly `{user}-demo`, the object is `Deployment/mongodb-nationalparks`, and the only changed container field is `image` with the approved tag. *Decline* if the tool proposes a Secret, Service, deletion, cross-namespace operation or unrelated field change.
. Approve the update. In *Workloads* -> *Deployments* -> `mongodb-nationalparks`, inspect *YAML* and verify that `spec.template.spec.containers[].image` now reads:
+
[source,text]
----
quay.io/mongodb/mongodb-community-server:8.0.32-ubi9-slim
----
. Wait for the replacement MongoDB Pod to become Ready. Inspect its logs for MongoDB `8.0.x` startup and successful initialization of the application's database user. Then retry `/ws/data/all`. It should respond without a driver compatibility error (an empty list is expected until data is loaded).

[IMPORTANT]
====
`resources_create_or_update` performs **server-side apply using a complete resource**, not a partial image patch. It might be hidden by MCP configuration, blocked by RBAC or rejected by field ownership. The student's instruction to approve a change does not grant permissions. If the tool is unavailable or its update fails, *stop and show the instructor*: record *MCP write unavailable* and use the instructor's console-recovery path only after approval. An AI-generated YAML snippet without a successful tool call is not an MCP update.
====

== Mission 6: Restore the National Parks map (5 minutes)

. Open menu:Networking[Routes] -> `nationalparks` and copy its URL.
. Visit `/ws/data/all` on the backend first. An empty array (`[]`) now means the database is reachable but park data has not yet been loaded.
. *Once*, for your disposable workshop database only, open the backend URL with `/ws/data/load` appended. This endpoint *changes* the database, so never use it as a recurring health check.
. Reload `/ws/data/all` and verify that it returns a non-empty array of parks. A response from `/ws/healthz/` alone does not prove the database works.
. Open the `parksmap` Route again and refresh the map. You should now see park markers; select one.

== Troubleshooting quick reference

[cols="2,3",options="header"]
|===
| Symptom | Action
| `{user}-demo` is not visible | Ask the instructor to grant access to the existing workshop project. Do not create a new project or deploy into `default`.
| *Error loading projects* on the image form | Confirm you can select `{user}-demo`; report the project-access error instead of selecting another namespace.
| Image import fails | Verify the external registry is reachable. Use the prepared instructor recovery path; do not substitute untested images.
| Python build is not ready | Open its Build details/logs and report the actual error. It may exceed this 45-minute timebox.
| `Couldn't create container` / `secret "nationalparks-mongodb-parameters" not found` | In *Workloads* -> *Secrets*, check that **you created** `nationalparks-mongodb-parameters` in `{user}-demo` with the exact spelling. If missing, create it using Mission 3. Do not remove `envFrom` or delete the Deployment; OpenShift retries after the Secret exists.
| MongoDB is not Ready | Confirm your Secret and `mongodb-nationalparks-bootstrap` ConfigMap exist in the correct project; report pull failures, UID/volume permission errors or Pod events without exposing credentials.
| `cannot translate opcode 2013` / Python `ServerSelectionTimeoutError` | *Expected in Mission 3.* MongoDB 3.2 cannot process the current PyMongo driver protocol. Proceed to the MCP troubleshooting and image-recovery missions; do not change the database Secret.
| MongoDB 8 starts but app authentication fails | Inspect MongoDB bootstrap logs for `createUser` errors and check the ConfigMap volume is mounted. Do not expose or recreate the student's Secret; ask the instructor to check its *key names* and initialization only.
| MCP reports `resources_create_or_update` unavailable, forbidden or conflict | Do not invent a successful tool result. Record *MCP write unavailable*, retain the diagnosis and ask the instructor for the console-only recovery procedure.
| Map has no markers after recovery | Check `/ws/data/all` is non-empty, the backend Route has `type=parksmap-backend`, and the frontend has service-discovery permissions.
| Lightspeed has no successful live tool result | Use the console for evidence and mark MCP access as unverified.
|===

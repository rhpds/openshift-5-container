= Mission National Parks: Deploy with the OpenShift 5 Console
:navtitle: Mission National Parks
:page-toclevels: 2
:experimental:

The National Parks application has not been deployed to your workshop project yet. Your project may already contain Showroom, GitOps or other workshop services; leave those resources alone. As the platform engineer, you will deploy the frontend, build the Python API from Git and create your own database Secret. The supplied MongoDB Deployment has a *deliberately outdated image*: you will use OpenShift Lightspeed and its built-in Kubernetes MCP integration to diagnose the failure, then apply the verified image-only fix yourself in the OpenShift console. Finally, you will load real park data and recover the map.

This is a *50-minute, console-first deployment and recovery mission* using *OpenShift Lightspeed 2.0*. Image deployment, Git import, Secrets, Routes, Services and the YAML editor are established OpenShift capabilities; the updated Project Felt interface and Lightspeed 2.0 *Troubleshooting* mode, with reviewed live MCP read calls, are the OpenShift 5 experiences in this mission.

The legacy ParksMap frontend watches Kubernetes *Routes*, *Services* and backend *Endpoints* to find data providers. . Check that the RoleBinding subject's `namespace` has automatically resolved to **`{user}-demo`**, matching the project selector. There is no placeholder to edit: copy the YAML from this rendered guide. The YAML creates one ServiceAccount, one Role and one RoleBinding; it does not create a new namespace or grant access to Secrets.

It must appear in the **Deployment's Pod template**, alongside `containers`, not in the ServiceAccount or RoleBinding YAML. If it is absent, the Pod uses `default` even though your new `parksmap-discovery` Role and RoleBinding exist. Add the field in the correct location, save and wait for a fresh Pod before proceeding.

== Mission 4: Diagnose the failure with Lightspeed MCP (6 minutes)

Use *OpenShift Lightspeed 2.0* to find out why the map has no data. Lightspeed will investigate; **you will make the fix** in Mission 5.

. Open *OpenShift Lightspeed* in the console and select *Troubleshooting*. If this mode is missing, ask your instructor.
+
image::module01-s09k-lightspeed-mode.png[OpenShift Lightspeed mode selector with Troubleshooting selected, width=900]
. Paste the prompt below:
+
[source,text,subs="attributes+"]
----
My National Parks application isn't displaying park data.

Use live Kubernetes MCP tools only in namespace {user}-demo.
Inspect the nationalparks and mongodb-nationalparks Deployments,
Pod status and recent logs.

Identify the most likely cause. Show the three strongest clues from
the live tools and explain them in simple terms.

Do not read Secrets or change any resources.
----
+
image::module01-s09l-lightspeed-prompt.png[Read-only Troubleshooting prompt scoped to the student's namespace, width=650]
. Let Lightspeed inspect the live resources. **No approval popup?** That's fine. If one appears, approve *only* read actions in `{user}-demo`; reject Secret access or changes.
. Look for these three clues:

[cols="1,3",options="header"]
|===
| Clue | What it means
| MongoDB log: `cannot translate opcode 2013` | MongoDB cannot understand the app's database messages.
| API log: `/ws/data/all` returns `500` or times out | The map cannot get its park data.
| MongoDB version `3.2.10` | The database is too old for the current Python driver.
|===

[TIP]
====
*AI check:* Lightspeed might correctly diagnose the fault but suggest an outdated MongoDB image. Ignore unverified image suggestions; use the approved MongoDB 8 image in Mission 5. The opcode error means MongoDB rejected a connection, not necessarily that its Pod crashed.
====

*Checkpoint 4:* You can explain why **Running Pods** can still produce a broken application. Lightspeed has not changed anything.

== Mission 5: Apply the MongoDB image fix in the console (10 minutes)

You have found the cause. Now update **one field** in the OpenShift console.

. In project `{user}-demo`, open *Workloads* -> *Deployments* -> `mongodb-nationalparks` -> *YAML* -> *Edit*.
. Find the `mongodb` container under `spec.template.spec.containers` and replace **only** its `image` value with:
+
[source,yaml]
----
image: quay.io/mongodb/mongodb-community-server:8.0.32-ubi9-slim
----
. Select *Save*. **Keep everything else unchanged**, including the Secret, environment variables and volumes. Wait for the new MongoDB Pod to become *Ready*.
. Open the new Pod's *Logs* and confirm MongoDB `8.0.x` starts without the old opcode error.
. Refresh the backend `/ws/data/all` endpoint. An empty array (`[]`) is now OK; you'll load the data next.

[IMPORTANT]
====
*Lab only:* This database uses temporary storage. Never use this image-swap procedure to upgrade a production MongoDB database. If the Pod fails, show your instructor the events and logs; do not expose passwords.
====

*Checkpoint 5:* MongoDB 8 is Ready, and **the container image was the only field you changed**.

== Mission 6: Restore the National Parks map (5 minutes)

. In *Networking* -> *Routes*, open the Python backend Route (`nationalparks` or `national-parks-app`).
. Open its `/ws/data/load` URL **once** to load parks into this disposable database. This changes data; do not use it as a health check.
. Open `/ws/data/all`. You should see a JSON list of park names and coordinates, not `[]`.
. Open the `parksmap` Route's `/ws/backends/list` URL. It should list `nationalparks` (or `national-parks-app`), not `[]`.
. Refresh the ParksMap page. You should see **park markers** and the *National Parks (PY)* layer.

Then check that the backend Service and Route have `type=parksmap-backend`. Do not reload the database to fix discovery.

== Troubleshooting quick reference

[cols="2,3",options="header"]
|===
| Symptom | Action
| `{user}-demo` is not visible | Ask the instructor to grant access to the existing workshop project. Do not create a new project or deploy into `default`.
| *Error loading projects* on the image form | Confirm you can select `{user}-demo`; report the project-access error instead of selecting another namespace.
| Image import fails | Verify the external registry is reachable. Use the prepared instructor recovery path; do not substitute untested images.
| Python build is not ready | Open its Build details/logs and report the actual error. It may exceed this 50-minute timebox.
| `Couldn't create container` / `secret "nationalparks-mongodb-parameters" not found` | In *Workloads* -> *Secrets*, check that **you created** `nationalparks-mongodb-parameters` in `{user}-demo` with the exact spelling. If missing, create it using Mission 3. Do not remove `envFrom` or delete the Deployment; OpenShift retries after the Secret exists.
| MongoDB is not Ready | Confirm your Secret and `mongodb-nationalparks-bootstrap` ConfigMap exist in the correct project; report pull failures, UID/volume permission errors or Pod events without exposing credentials.
| `cannot translate opcode 2013` / Python `ServerSelectionTimeoutError` | *Expected in Mission 3.* MongoDB 3.2 cannot process the current PyMongo driver protocol. Proceed to the MCP troubleshooting and image-recovery missions; do not change the database Secret.
| MongoDB 8 starts but app authentication fails | Inspect MongoDB bootstrap logs for `createUser` errors and check the ConfigMap volume is mounted. Do not expose or recreate the student's Secret; ask the instructor to check its *key names* and initialization only.
| MCP reports `resources_create_or_update` unavailable | This was observed with the workshop's Lightspeed 2.0 built-in toolset. Continue with Mission 5's human-applied Deployment image change. No additional MCP server is needed.
| Lightspeed does not offer *Troubleshooting* | Ask the instructor to verify Operator 2.0, `OLSConfig` readiness, model connectivity and built-in MCP tool access. Do not install another MCP server or grant cluster-wide permissions.
| Map has no markers after recovery | If `/ws/data/all` is populated but `/ws/backends/list` returns `[]`, **first check the `parksmap` Deployment Pod template includes `serviceAccountName: parksmap-discovery`**. Creating the RoleBinding alone does not switch the Deployment away from `default`. Then check the backend *Service* and *Route* have `type=parksmap-backend`, and the discovery Role allows Routes and Services `get/list/watch` plus named backend Endpoints `get/watch`. Inspect ParksMap logs for `Forbidden` before changing anything. Do not reload the database to fix frontend discovery.
| ParksMap Route says *Application is not available* | Check Pod restarts and readiness, `oc get endpoints parksmap`, and prior container logs. A crash loop can follow repeated failed Kubernetes watches; fix the precise missing permission before a controlled restart. Do not restart all project Pods.
| Lightspeed has no successful live tool result | Use the console for evidence and mark MCP access as unverified.
|===

= Mission National Parks: Deploy with the OpenShift 5 Console
:navtitle: Mission National Parks
:page-toclevels: 2
:experimental:

The National Parks application has not been deployed to your workshop project yet. Your project may already contain Showroom, GitOps or other workshop services; leave those resources alone. As the platform engineer, you will deploy the frontend, build the Python API from Git, add its database, and confirm that real park data reaches the browser. Then you will use OpenShift Lightspeed to investigate what you created.

This is a *25-minute, console-first deployment mission*. The image deployment, Git import, Routes, Services and YAML editor are established OpenShift capabilities; the updated Project Felt interface and live MCP-assisted investigation are the OpenShift 5 experiences in this mission.

| Select project | Frontend | Python API | MongoDB | Map online | MCP challenge | Sign-off
|===

[IMPORTANT]
.Before you begin
====
* Sign in as `{lab_user}`, then select your *existing* workshop project **`{lab_user}-demo`** (for example, `user-pjbsb-demo`). **Do not create a project.** Do not deploy into `default` or `{lab_user}`.
* Your instructor must prepare the database Secret named `nationalparks-mongodb-parameters`, safe namespace-scoped service discovery permissions, accessible image registries and a working Dockerfile/BuildConfig build path **in `{lab_user}-demo`** before class. * This 25-minute target depends on rehearsed registry pulls, Dockerfile build time and database start time. If a build stalls, capture its status and ask the instructor for the prepared recovery path.

== Mission 0: Select your existing workshop project (2 minutes)

. In Showroom, select the *OCP Console* tab or open {openshift_console_url}[your OpenShift console]. Sign in as `{lab_user}`.
. Open *Projects* (from *Home* or your console's project navigation). Locate and open **`{lab_user}-demo`**. If you cannot see it, stop and ask the instructor to grant access; do **not** click *Create Project*.
. Confirm the selected project is `{lab_user}-demo`. Explore the new OpenShift 5 Project Felt appearance.
+
image::module01-s00-console.png[OpenShift 5 Projects view showing the student's existing demo project, width=900]

. Open *Workloads* -> *Secrets* in this project and look for `nationalparks-mongodb-parameters`. Confirm its **name only**; do not open or copy its data values. If the Secret is not listed, or you cannot check it, stop and ask the instructor to verify/provision it in `{lab_user}-demo` **before continuing**. A Secret in a different namespace cannot be used here.
. Open *Topology* from the workload navigation and confirm there is no `national-parks-app` grouping yet. Existing Argo CD, Gitea or other workshop workloads are expected and must be left alone.

*Predict:* How many Deployments and public Routes will our three-tier application eventually need?

*Checkpoint 0:* You have selected `{lab_user}-demo`, confirmed that the instructor-provided MongoDB Secret is available, and confirmed National Parks is not yet deployed. You did not create a new namespace or modify the existing workshop services.

== Mission 1: Put the frontend online (4 minutes)

The fastest way to begin is with an existing container image. A running frontend does not mean the application has its data yet.

. While `{lab_user}-demo` is selected, open the console's *Quick create* (`+`) menu at the top of the page and choose *Container images*. If the menu layout differs, find the console's create-application-from-image action.
+
image::module01-s05a-container-images-menu.png[OpenShift 5 Quick create menu - choose Container images to deploy the frontend, width=900]

. On the *Deploy Image* page, select *Image name from external registry*. Verify that *Select project* shows `{lab_user}-demo` and enter:
+
[source,text]
----
quay.io/openshiftroadshow/parksmap:latest
----
+
image::module01-s05b-image-and-project.png[Deploy Image: validated external registry image and existing user demo project selected, width=900]

. Leave *Runtime icon* set to **openshift**. Under *Application*, choose *Create application*. Enter *Application name*: `national-parks-app`, and *Name*: `parksmap`.
+
image::module01-s05c-runtime-and-app.png[Deploy Image: OpenShift runtime icon, Create application and parksmap component name, width=900]

. Under *Deploy*, choose *Resource type*: **Deployment**. Keep *Target port*: `8080`, and ensure *Create a route* is checked.
+
image::module01-s05d-deployment-and-route.png[Deploy Image: Deployment, target port 8080 and Create a route enabled, width=900]

. Under *Labels*, add these exact entries. Keep any console-generated labels that do not conflict:
+
[source,text]
----
app=national-parks-app
component=parksmap
role=frontend
app.kubernetes.io/part-of=national-parks-app
----
+
image::module01-s05e-frontend-labels.png[Deploy Image: the four frontend application labels, width=900]

. Select *Create*. The console normally opens *Topology* after creating the Deployment. If it does not, open the top-left navigation menu, expand *Workloads*, and select *Topology*. Confirm that the project is still `{lab_user}-demo`.
+
image::module01-s05f-topology-navigation.png[OpenShift 5 Workloads navigation expanded with Topology selected and parksmap showing one Pod, width=900]

. In the `national-parks-app` group, select `parksmap` and wait until its ring is healthy and the details panel shows *1 Pod*. A suggestion to add health checks is not, by itself, a deployment failure.
. In the Topology diagram, hover over the `parksmap` component and select the external-link icon labelled *Open URL*. This opens the frontend's Route in a new browser tab.
+
image::module01-s05g-open-url.png[OpenShift 5 Topology showing the parksmap component and Open URL external-link icon, width=900]

. Your browser may ask whether the site can *Know your location*. You can select *Allow this time* if you are comfortable sharing your location with the page. If you decline, tell your instructor if the map or its backend layers fail to update; this older frontend does not handle a denied location request reliably. Browser location permission is *not* an OpenShift permission.
+
image::module01-s05h-location-permission.png[Browser location permission dialog for the new parksmap Route, width=650]

. Confirm that the page opens with a world map. It is normal for the initial map to have no park markers: the API and database have not been deployed yet.
+
image::module01-s05i-frontend-first-open.png[Initial parksmap page showing the world map before the backend is connected, width=900]

[NOTE]
====
The page heading *Map Visualizer on OpenShift 4* is literal text in the https://github.com/openshift-roadshow/parksmap-web/blob/master/src/main/resources/static/index.html[legacy ParksMap frontend source]. It does **not** report your cluster's version: you are deploying the image to OpenShift 5. There is no verified OpenShift 5-specific replacement image in this workshop, so keep the tested `quay.io/openshiftroadshow/parksmap:latest` image.
====

*What do you notice?* The map application can be reachable before any park data is displayed. It still needs the Python API and MongoDB. Do not troubleshoot the empty map yet.

*Checkpoint 1:* One Ready `parksmap` Deployment, a Service and a browser-accessible Route exist in **your** project.

== Mission 2: Build the Python backend from Git (6 minutes)

The map now has a frontend, but it still needs a Python API. In this mission you will import its source code, watch OpenShift build a container image, and check that the backend answers HTTP requests.

. With *{lab_user}-demo* selected, choose *Quick create* (`+`) -> *Import from Git*. Enter the repository below. Confirm *Select project* shows your own `{lab_user}-demo` project, not the example student's project in the screenshot.
+
[source,text]
----
https://github.com/openshift-roadshow/nationalparks-py.git
----
+
image::module01-s06a-git-repository.png[Import from Git: validated Python backend Git URL and the student's existing project, width=900]

. Wait for the import strategy detection. The console recommends *Dockerfile* because this repository contains one. **Keep the recommended Dockerfile**: it uses a UBI 9 Python 3.12 base image. You do not need to switch to a different Python builder.
. In *General*, set *Application* to the existing `national-parks-app` and *Name* to `nationalparks`. Under *Build*, choose *Build option: BuildConfig*. This creates a BuildConfig that tracks the source build; it is different from the Deployment that will run the resulting image.
+
image::module01-s06b-buildconfig-settings.png[Import from Git: national-parks-app grouping, nationalparks component name and BuildConfig selected, width=900]

. In *Deploy*, select *Resource type: Deployment*. Keep *Target port: 8080* and *Create a route* checked. OpenShift will expose the backend through a Service and an external Route.
+
image::module01-s06c-deployment-route.png[Import from Git: Deployment resource type, target port 8080 and Create a route checked, width=900]

. In *Labels*, add all five values below. Keep any other generated labels that do not conflict.
+
[source,text]
----
app=national-parks-app
app.kubernetes.io/part-of=national-parks-app
component=nationalparks
role=backend
type=parksmap-backend
----
+
image::module01-s06d-backend-labels.png[Import from Git: the backend's five application labels, width=900]

. Select *Create*. Open the top-left console navigation, expand *Builds*, and choose *Builds*. Make sure the selected project is still `{lab_user}-demo`.
+
image::module01-s06e-builds-navigation.png[OpenShift 5 navigation: Builds section expanded and Builds selected, width=650]

. Find the build named `nationalparks-1` (or your project's latest `nationalparks` build), open it and select the *Logs* tab. Wait for its status to show *Complete*. At the end of the build log, look for **Successfully pushed** and **Push successful**. These lines confirm the container image was built and stored in the OpenShift image registry. If the build fails, inspect the error in this tab and ask your instructor; do not change the import strategy at random.
+
image::module01-s06f-build-success-logs.png[Build nationalparks-1: Complete status and build log ending with Successfully pushed and Push successful, width=900]

. Return to *Workloads* -> *Topology*. Select `nationalparks` in the `national-parks-app` group and open its *Resources* tab. Confirm that the build is marked *Complete* and its Pod is *Running*. The *View logs* link beside the Pod shows **runtime logs**, while the *View logs* link beside the Build shows **image-build logs**. These are different troubleshooting views.
+
image::module01-s06g-topology-resources.png[Topology: parksmap and nationalparks in one application, with running backend Pod and completed Build, width=900]

. To test the backend Route, open the top-left navigation menu, expand *Networking*, and choose *Routes*. Find the `nationalparks` Route in `{lab_user}-demo`. Do not choose `parksmap`, which is the frontend Route. In the screenshot, the route's *Backend health* is `1/1`.
+
image::module01-s06h-backend-routes.png[OpenShift 5 Routes page showing a healthy nationalparks backend Route alongside parksmap and workshop Routes, width=900]

. Select the `nationalparks` Route name. On its details page, locate the *Location* URL (the Route hostname) and open the link in a new browser tab. The page should display:
+
[source,text]
----
Welcome to the National Parks data service.
----
+
image::module01-s06i-backend-welcome.png[Browser displaying Welcome to the National Parks data service from the nationalparks Route, width=900]

[IMPORTANT]
====
This welcome message confirms that the backend is reachable over HTTP. It **does not** prove that park records are available yet: you will connect MongoDB in Mission 3 and load data in Mission 4. Do not call `/ws/data/load` now.
====

[NOTE]
====
The frontend discovers the API using a **Route** labelled `type=parksmap-backend`. On *Networking* -> *Routes* -> `nationalparks` -> *YAML*, confirm that `metadata.labels` contains this value. If the label is missing, add it to the **Route** using the YAML editor and save. A label on the Deployment alone is insufficient for Route discovery.
====

*Checkpoint 2:* The `nationalparks` BuildConfig has produced a *Complete* build, the backend Pod is *Running*, the Service and Route exist, and the Route's URL displays **Welcome to the National Parks data service.** Park data will be added later.

== Mission 3: Add the database from YAML (5 minutes)

Before starting this mission, confirm the prerequisite from Mission 0: a lab-only Secret named `nationalparks-mongodb-parameters` must exist in **the same `{lab_user}-demo` project**. It supplies the database settings to *both* MongoDB and the Python backend. The database YAML below **does not create the Secret**. If it is missing, ask the instructor to provision it and wait; do not proceed with the YAML import or the backend `envFrom` edit. Never paste Secret values into the lab guide or an AI chat.

. In the console, select *Quick create* (`+`) -> *Import YAML* (sometimes labelled *YAML* or *Create from YAML*).
. Copy the following prepared **two-resource** manifest into the editor. It creates a MongoDB Deployment and an internal Service, but no public Route. The password comes from the existing Secret.

[source,yaml]
----
include::example$module01-mongodb.yaml[]

. Review the resources: `Deployment/mongodb-nationalparks` and `Service/mongodb-nationalparks`. Select *Create*.
. Open menu:Workloads[Deployments] -> `nationalparks` -> *YAML*. In its existing application container, add the following field under that container's properties (preserve its existing `image`, `ports` and other fields):

[source,yaml]

----

If the new Pod reports `secret "nationalparks-mongodb-parameters" not found`, the reference is correctly placed but the prerequisite is missing from this namespace. == Mission 4: Bring National Parks to life (3 minutes)

. Open menu:Networking[Routes] -> `nationalparks`, and copy its URL.
. **Once**, for your disposable workshop database only, open the backend URL with `/ws/data/load` appended. This endpoint *changes* the database, so never use it as a recurring health check.
. Open the backend `/ws/data/all` endpoint and verify that it returns a non-empty array of parks. A response from `/ws/healthz/` alone does not prove the database works.
. Open the `parksmap` Route again and refresh the map. You should now see park markers; select one.
. Return to *Topology* and identify `parksmap`, `nationalparks` and `mongodb-nationalparks` in the `national-parks-app` group.

== Mission 5: Verify the live application using OpenShift 5 MCP (4 minutes)

The *MCP server for Red Hat OpenShift* is a key OpenShift 5 feature. Your instructor has configured the Lightspeed read path separately; use it to check real resources, not to run deployment or scaling commands.

. Open *OpenShift Lightspeed* from the console chat icon.
. Send this read-only prompt, scoped to your application namespace:
+
[source,text,subs="attributes+"]
----
Use the live OpenShift MCP read tools only in namespace {lab_user}-demo.
Inspect Deployments parksmap, nationalparks and mongodb-nationalparks;
Services parksmap, nationalparks and mongodb-nationalparks;
and Routes parksmap and nationalparks.

Report ready replica counts, which Services have public Routes,
and the actual Route hostnames. Show the successful tool calls
and their resource evidence. If live tools are unavailable,
say so explicitly. Do not inspect Secrets or change resources.
----
. Verify at least one Deployment and Route yourself in *Topology* and menu:Networking[Routes].

image::module01-s07-lightspeed.png[Placeholder S07 - recapture real Lightspeed MCP tool evidence matching the OpenShift console, width=900]

*Checkpoint 5:* Mark one honest result: *verified MCP live read*, *AI interpreted supplied text only*, or *live MCP unavailable*. A fluent response without a successful tool result is not evidence.

== Troubleshooting quick reference

[cols="2,3",options="header"]
|===
| Symptom | Action
| `{lab_user}-demo` is not visible | Ask the instructor to grant access to the existing workshop project. Do not create a new project or deploy into `default`.
| *Error loading projects* on the image form | Confirm you can select `{lab_user}-demo`; report the project-access error instead of selecting another namespace.
| Image import fails | Verify the external registry is reachable. Use the prepared instructor recovery path; do not substitute untested images.
| Python build is not ready | Open its Build details/logs and report the actual error. It may exceed this 25-minute timebox.
| `Couldn't create container` / `secret "nationalparks-mongodb-parameters" not found` | The referenced Secret was not provisioned in `{lab_user}-demo`. Ask the instructor to create it in this exact project. Do not remove `envFrom`, invent credentials, or delete the Deployment; OpenShift will retry after the Secret is available.
| MongoDB is not Ready | Check that the instructor-provided Secret exists; report pull failures or pod events without exposing credentials.
| Map has no markers | Confirm the backend Route's `type=parksmap-backend` label, service discovery permissions and non-empty `/ws/data/all`.
| Lightspeed has no successful tool result | Use the console for verification and mark MCP access as unverified.
|===

== Start here: Log in to OpenShift

Open the Showroom *Terminal* tab and authenticate using your assigned workshop credentials *before running any other +oc+ commands*:

[source,bash,subs="attributes+",role=execute]
----
oc login --server={openshift_api_url} --username={user} --password='{password}' --insecure-skip-tls-verify
oc whoami
----

Verify that +oc whoami+ returns {user}. This is a disposable lab environment: the + -p + option can expose your password in shell history and process listings. Do not reuse this password on a personal or production cluster.


Module 4 ended with a healthy WeatherNow app in +{user}-gitops+. The fault was a bad *readiness probe*. Module 5 introduces a separate release failure: the new WeatherNow image tag does not exist, so the new ReplicaSet cannot pull it. Students diagnose the failed rollout, investigate with Lightspeed and namespaced Kubernetes evidence, and restore the source through Gitea.

This does not repeat Module 4's incident and does not modify either National Parks stack.

*Duration: 30 minutes.*

[cols="1,3",options="header"]
|===
| Time | Mission
| 4 min | 1 — Check a healthy WeatherNow rollout and GitOps source
| 6 min | 2 — Commit a bad image tag and observe ImagePullBackOff
| 8 min | 3 — Diagnose the rollout using Lightspeed and live evidence
| 7 min | 4 — Review image-pull evidence and recovery
| 5 min | 5 — Restore the image in Git and verify release recovery
|===

[IMPORTANT]
.Safety and ownership
====
* All changes happen in *your own Gitea main branch*, in the separate WeatherNow path.
* +Application/weathernow-lab+ and +Deployment/weathernow+ live in +{user}-gitops+.
* Do not change the National Parks manifests, Shared ClusterResourceQuota, Secrets, Namespace, ApprovalPolicy, or Argo CD controller.
* Do not patch the live Deployment or issue +oc rollout undo+: GitOps would eventually restore its declared state. Repair the Git source instead.
* Student AgenticRuns are temporarily deferred pending cross-namespace sandbox and isolation fixes. No run or approval is required.
====

== Mission 1: Confirm the healthy release baseline (4 minutes)

. Use the student project and verify Module 4 was repaired:
+
[source,bash,subs="attributes+",role=execute]
----
export STUDENT="$(oc whoami)"
export NS="$STUDENT-gitops"
oc get deployment weathernow -n "$NS" \
  -o custom-columns='NAME:.metadata.name,READY:.status.readyReplicas,IMAGE:.spec.template.spec.containers[0].image'
oc get application weathernow-lab -n "$NS" -o json | \
  jq '{sync:.status.sync.status, health:.status.health.status, revision:.status.sync.revision}'
oc get deployment weathernow -n "$NS" -o json | \
  jq '.spec.template.spec.containers[0].readinessProbe'
----
+
*Expected:* WeatherNow 1/1 Ready, image +quay.io/openshift-workshop-applications/weathernow:latest+, readiness probe port +http+, GitOps Synced/Healthy. If Module 4 is not recovered, stop and repair it first.
+
image::module05-s01-weather-baseline.svg[S01: healthy WeatherNow image and GitOps baseline, screenshot placeholder, width=850]

. Capture the working external Route:
+
[source,bash,subs="attributes+",role=execute]
----
export WEATHER_HOST="$(oc get route weathernow -n "$NS" -o jsonpath='{.spec.host}')"
curl -sS -o /dev/null -w 'WeatherNow HTTP %{http_code}\n' "https://$WEATHER_HOST/"
----
+

*Checkpoint 1:* The current image and Route work.

== Mission 2: Release an invalid image tag (6 minutes)

. In *Gitea*, sign in as `{user}` with password `{password}` if prompted, then open the student-owned repository +main+ and this file:
+
[source,text,role=copypaste]
----
weathernow/weathernow.yaml
----
+
Find the +Deployment/weathernow+ container image (not the Service or Route).
+
image::module05-s03-weather-image-source.svg[S03: WeatherNow image field in student Gitea, screenshot placeholder, width=850]

. Replace *only* this value:
+
[source,yaml,role=copypaste]
----
image: quay.io/openshift-workshop-applications/weathernow:latest
----
+
With a deliberately nonexistent tag:
+
[source,yaml,role=copypaste]
----
image: quay.io/openshift-workshop-applications/weathernow:module05-intentional-bad-tag
----
+
Do not edit the resource name, pull secrets, Service or quota. Commit:
+
[source,text,role=copypaste]
----
lab(module05): simulate WeatherNow image pull failure
----
+
image::module05-s04-weather-invalid-image.svg[S04: deliberately incorrect WeatherNow image tag and Gitea commit, screenshot placeholder, width=850]

. Observe the new Deployment generation and its image pull errors:
+
[source,bash,subs="attributes+",role=execute]
----
oc get application weathernow-lab -n "$NS" -o json | \
  jq '{sync:.status.sync.status, health:.status.health.status, revision:.status.sync.revision}'
oc get deployment weathernow -n "$NS" -o json | \
  jq '.spec.template.spec.containers[0].image'
oc get pods -n "$NS" -l app=weathernow
oc get events -n "$NS" --sort-by=.lastTimestamp | tail -20
----
+
The new Pod should eventually show +ErrImagePull+ or +ImagePullBackOff+. The old ready Pod may still serve the Route during RollingUpdate; record what actually happened.
+
image::module05-s05-weather-imagepull-events.svg[S05: new WeatherNow Pod image pull failure and events, screenshot placeholder, width=850]

*Checkpoint 2:* GitOps has accepted the wrong source revision and the new image cannot be pulled.

== Mission 3: Evidence-backed Lightspeed diagnosis (8 minutes)

. Open *Lightspeed → Troubleshooting* and ask:
+
[source,text,subs="attributes+"]
----
Investigate the new Deployment/weathernow revision in
namespace {user}-gitops. The current Gitea revision points
to a WeatherNow image tag that cannot be pulled.

Use read-only tools to inspect Deployment/ReplicaSet/Pod
conditions, image references, and Pod events. Compare the
new image with the last known working tag and explain
why an older ready Pod may still answer HTTP 200.
Explain Synced versus Healthy, give the smallest
source-controlled GitOps repair and cite actual evidence.
Do not read Secrets or change any resource.
Do not access other student namespaces.
----
+
image::module05-s06-weather-lightspeed-prompt.svg[S06: Lightspeed investigates WeatherNow image pull failure, screenshot placeholder, width=850]

. Independently verify:
+
[source,bash,subs="attributes+",role=execute]
----
oc get deployment weathernow -n "$NS" -o json | \
  jq '{image:.spec.template.spec.containers[0].image,available:.status.availableReplicas,updated:.status.updatedReplicas}'
oc get replicasets,pods -n "$NS" -l app=weathernow
oc describe deployment weathernow -n "$NS"
oc get events -n "$NS" --sort-by=.lastTimestamp | tail -20
----
+
An absent tag can cause +manifest unknown+ or similar registry errors; you should not invent a specific message. This is *not* a MongoDB fault, a scheduling issue, or a reason to modify cluster-wide registry credentials.
+
image::module05-s07-weather-registry-evidence.svg[S07: live image tag and pull failure events, screenshot placeholder, width=850]

*Checkpoint 3:* You can identify the exact wrong image and propose a Git commit restoring the old tag.

== Mission 4: Review failed release evidence and plan recovery (7 minutes)

[IMPORTANT]
.AgenticRuns temporarily deferred
====
Student-created AgenticRuns are *not part of this workshop* while cross-namespace sandbox lifecycle and tenant isolation remain unresolved. Do *not* create an AgenticRun or AgenticRunApproval, install +oc agentic+, or request additional permissions. Use OpenShift Lightspeed Troubleshooting, namespaced +oc+ evidence and GitOps. A sanitized instructor example may illustrate the lifecycle, but no live AgenticRun is required to complete the lab.
====

A failed image pull should be repaired in Git, not by changing the live Deployment.

. Inspect the image and recent image-pull events:
+
[source,bash,subs="attributes+",role=execute]
----
oc get deployment weathernow -n "$NS" -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'
oc get pods -n "$NS" -o wide
oc get events -n "$NS" --sort-by=.lastTimestamp | tail -15
----
+
. Compare +module05-intentional-bad-tag+ with the known-good image tag in student Gitea. Identify the source file and restore commit you will make in Mission 5.
. Explain the AgenticRun analysis -> proposal -> human decision boundary if the instructor supplies an example; do not create an AgenticRun.

*Checkpoint 4:* Record the bad image, related pull event and proposed Git correction. No AgenticRun is required.

== Mission 5: Repair Git, verify and close (5 minutes)

. In student Gitea +main+, restore:
+
[source,yaml,role=copypaste]
----
image: quay.io/openshift-workshop-applications/weathernow:latest
----
+
Commit:
+
[source,text,role=copypaste]
----
fix(module05): restore working WeatherNow image tag
----
+
image::module05-s11-weather-image-repair.svg[S11: WeatherNow image restored in student Gitea, screenshot placeholder, width=850]

. Validate the recovery commit against the previous bad revision. In Gitea, note the *full Git SHA* of the repair commit, which should be the desired revision for +weathernow-lab+. A Git revert commit or a corrective edit is appropriate; +oc rollout undo+ is *not* a durable recovery when Argo CD controls the desired state. Do not manually sync.
. Verify automatic reconciliation, the actual desired Git revision, readiness and a working new revision:
+
[source,bash,subs="attributes+",role=execute]
----
oc get deployment weathernow -n "$NS" -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'
oc rollout status deployment/weathernow -n "$NS" --timeout=120s
oc get application weathernow-lab -n "$NS" -o json | \
  jq '{desiredRevision:.status.sync.revision,sync:.status.sync.status,health:.status.health.status,operation:.status.operationState.phase}'
oc get replicasets,pods -n "$NS" -l app=weathernow
oc get events -n "$NS" --sort-by=.lastTimestamp | tail -10
curl -sS -o /dev/null -w 'WeatherNow HTTP %{http_code}\n' "https://$WEATHER_HOST/"
oc get deployment nationalparks parksmap mongodb-nationalparks -n "$NS"
oc get deployment nationalparks parksmap mongodb-nationalparks -n "$STUDENT-demo"
----
+
image::module05-s12-weather-final-healthy.svg[S12: restored WeatherNow GitOps release and unaffected National Parks workloads, screenshot placeholder, width=850]

*Checkpoint 5:* The restored image is running, the Application revision matches the Gitea repair commit, GitOps is Synced/Healthy, a replacement replica is Ready, Route returns HTTP 200 and both National Parks stacks remain healthy.

== Troubleshooting

[cols="2,3",options="header"]
|===
| Symptom | Check
| Invalid tag has no effect | Confirm Argo CD reconciled the student Gitea commit, not a GitHub copy
| Old Pod still serves HTTP 200 | Normal rolling update can preserve availability; inspect the new Pod and events
| AgenticRun unavailable | Expected during student-run deferral; use Lightspeed and GitOps evidence
| Recovery won't roll out | Check the live image tag, ReplicaSet/Pod Events, Deployment conditions and the exact Gitea commit against Application source revision; do not delete the App/PVC
| WeatherNow absent | Revisit Module 4 setup before starting Module 5
|===

= Module 2: GitOps Onboarding & Multitenancy
:navtitle: GitOps Onboarding & Multitenancy
:page-toclevels: 2
:experimental:

In Module 1, you repaired the MongoDB Service and got the National Parks map working.
Now you will use *Gitea*, *Argo CD* and *OpenShift Lightspeed 2.0* to manage a small part of that application's environment through Git.

*Duration:* approximately 30 minutes.

[cols="1,3",options="header"]
|===
| Time | Mission
| 5 min | Check your student account and ask Lightspeed what is deployed
| 5 min | Explore your Gitea repository
| 8 min | Create a manually synchronized Argo CD Application
| 7 min | Change Git, investigate with Lightspeed and synchronize
| 5 min | Check namespace isolation and application health
|===

[IMPORTANT]
====
*Your National Parks application stays running.* This lab manages **one harmless ConfigMap** associated with National Parks, not its Deployments, Secrets, Services or MongoDB settings. Your Module 1 fix will not be overwritten.

Argo CD synchronization is **manual**. Lightspeed uses MCP read tools to investigate and explain; **you** make Git and Argo CD changes. No MCP write tools, cluster-admin rights, new namespace or shared Git credentials are required.
====

== Mission 1: Check the environment with Lightspeed (5 minutes)

. Open the Showroom *Terminal* tab. As in Module 1, authenticate as your assigned student:
+
[source,bash,subs="attributes+"]
----
oc login {openshift_api_url} -u {user} -p {password}
oc whoami
oc project {user}-demo
----
+
Expected identity: `{user}`. If you see `system:serviceaccount:...:showroom`, stop and sign in as the student. Using `-p` displays your lab password in shell history; use only this disposable workshop terminal.

. Save your project and Application name for later:
+
[source,bash,subs="attributes+"]
----
export LAB_NAMESPACE={user}-demo
export ARGOCD_NAMESPACE=$LAB_NAMESPACE
export ARGOCD_APP=national-parks-settings
oc get deployments -n "$LAB_NAMESPACE" \
  -l app.kubernetes.io/part-of=national-parks-app
oc get applications.argoproj.io -n "$LAB_NAMESPACE"
----
+
Your National Parks workloads should be running. It is **normal for the Applications list to be empty**: an Argo CD *instance* is already installed, but the National Parks GitOps Application has not yet been created.

. Open *OpenShift Lightspeed* -> *Troubleshooting* and paste:
+
[source,text,subs="attributes+"]
----
Use live Kubernetes tools to inspect the Argo CD instance,
Applications and ConfigMaps in namespace {user}-demo.

Tell me what GitOps resources already exist and what is missing.
Do not read Secrets or change anything.
----
+
Approve only **read** operations for your own namespace. Lightspeed should distinguish the existing Argo CD instance from an Argo CD Application. If the MCP tool cannot read an Argo CD custom resource, use the `oc get` commands above as the source of truth; do not accept an invented resource.

*Checkpoint 1:* You can explain why installing Argo CD does not automatically put National Parks under GitOps management.

== Mission 2: Find your GitOps source in Gitea (5 minutes)

Each student has a separate Gitea instance and repository.

. Open Showroom's *Gitea* tab. If it is missing, open *Networking* -> *Routes* in your project and follow the Gitea Route's *Location* link.
. Sign in using your assigned student Gitea account (typically `{user}`). Gitea credentials may differ from your OpenShift login; the workshop bootstrap defaults are documented by your instructor.
. Open the repository **`openshift-5-container`**. It is imported into your Gitea instance from the public workshop source.
. Browse to:
+
[source,text]
----
content/modules/ROOT/examples/module02-gitops/
  kustomization.yaml
  national-parks-gitops-info.yaml
----
. Open `national-parks-gitops-info.yaml`. The initial message is:
+
[source,yaml]
----
data:
  message: "GitOps baseline"
----
. Select the repository's *Clone* button and copy its **HTTPS** URL. You will paste this into Argo CD. Use the Gitea URL, **not** the GitHub URL. Confirm the repository is public/readable by Argo CD; never embed a password or token in the URL.

[NOTE]
====
If `openshift-5-container` or `module02-gitops` is absent, stop and ask your instructor to re-run repository migration **after** this workshop update has been merged. Do not create an empty repository or guess the source path.
====

*Checkpoint 2:* You have a real Gitea HTTPS repository URL and can see the two GitOps files.

== Mission 3: Onboard one resource into Argo CD (8 minutes)

. Open Showroom's *ArgoCD* tab. Sign in with *OpenShift* SSO if prompted.
. Select *+ NEW APP* (or *New App*) and use these values:

[cols="2,3",options="header"]
|===
| Field | Value
| Application name | `national-parks-settings`
| Project | `default`
| Sync policy | **Manual** (do not enable automatic sync, prune or self-heal)
| Repository URL | Your Gitea HTTPS clone URL from Mission 2
| Revision | `HEAD` (or the repository's default branch)
| Path | `content/modules/ROOT/examples/module02-gitops`
| Cluster | `https://kubernetes.default.svc`
| Namespace | `{user}-demo`
|===

. Select *Create*. The new Application may show **OutOfSync** and **Missing**. That is expected: the ConfigMap exists in Git but has not been applied.
. Open the Application and inspect the change. It should propose **one ConfigMap** named `national-parks-gitops-info`. If it proposes a Deployment, Secret, Service, Route or namespace, **do not sync**; the wrong repository/path was selected.
. Select *Sync*, review the resource, then *Synchronize*. Leave prune and force disabled.
. Confirm from the student terminal:
+
[source,bash]
----
oc get applications.argoproj.io national-parks-settings \
  -n "$LAB_NAMESPACE" \
  -o jsonpath='{.status.sync.status}{" / "}{.status.health.status}{"\n"}'

oc get configmap national-parks-gitops-info \
  -n "$LAB_NAMESPACE" \
  -o jsonpath='{.data.message}{"\n"}'
----
+
Expected: `Synced / Healthy` and `GitOps baseline`. A brief `Progressing` or `Unknown` state is possible while Argo CD refreshes; check its resource tree before proceeding.

*Checkpoint 3:* Argo CD now manages exactly one ConfigMap in *your* namespace. The running National Parks application remains unchanged.

== Mission 4: Change Git, investigate with Lightspeed, then sync (7 minutes)

. In *Gitea*, edit `content/modules/ROOT/examples/module02-gitops/national-parks-gitops-info.yaml` in your own repository. Change **only** this value:
+
[source,yaml]
----
message: "Updated in Gitea"
----
. Commit the change directly to the branch Argo CD is tracking. Do not edit any Secret or workload manifest.
. In *ArgoCD*, open `national-parks-settings` and select *Refresh*. The Application should become **OutOfSync**. The live ConfigMap still has `GitOps baseline` because automatic sync is disabled.
. Before syncing, ask Lightspeed:
+
[source,text,subs="attributes+"]
----
I updated Git, but ConfigMap national-parks-gitops-info
still shows the old message in namespace {user}-demo.

Use live Kubernetes tools to inspect the Argo CD Application
and the ConfigMap. Explain why it has not changed.

Do not read Secrets or change anything.
----
+
A useful diagnosis is that the Application uses **manual synchronization** and needs a reviewed Sync. MCP may not be able to inspect the Git commit itself; confirm Git changes in Gitea and the Application status in Argo CD.

. In the Argo CD Application, select *Sync* -> *Synchronize*.
. Verify the change:
+
[source,bash]
----
oc get configmap national-parks-gitops-info \
  -n "$LAB_NAMESPACE" \
  -o jsonpath='{.data.message}{"\n"}'
----
+
Expected: `Updated in Gitea`.

*Checkpoint 4:* You saw **Git commit -> OutOfSync -> manual Sync -> updated cluster ConfigMap**. Lightspeed helped investigate but did not modify the cluster.

== Mission 5: Confirm multitenancy and app health (5 minutes)

A GitOps Application has a target namespace; Kubernetes RBAC separately controls who can change resources there.

. In the Terminal, compare your rights:
+
[source,bash]
----
oc auth can-i patch deployments.apps -n "$LAB_NAMESPACE"
oc auth can-i patch deployments.apps -n openshift-config
----
+
Normally the first check is `yes` and the second is `no`. If the result differs, record it and ask the instructor: access is determined by your actual cluster RBAC.

. Inspect the namespace-scoped discovery RoleBinding and the GitOps destination:
+
[source,bash]
----
oc get rolebinding parksmap-discovery -n "$LAB_NAMESPACE" \
  -o jsonpath='{.subjects[0].name}{"\n"}'

oc get applications.argoproj.io national-parks-settings \
  -n "$LAB_NAMESPACE" \
  -o jsonpath='{.spec.destination.namespace}{"\n"}'
----
+
Expected: `parksmap-discovery` and your own `{user}-demo` namespace.

. Check that the map still works: https://parksmap-{user}-demo.{openshift_cluster_ingress_domain}/[Open ParksMap,window=_blank] and https://national-parks-app-{user}-demo.{openshift_cluster_ingress_domain}/ws/data/all[View park data,window=_blank].

*Checkpoint 5:* You have isolated student permissions, a manually synchronized ConfigMap, and a healthy National Parks application.

== Mission complete

You used *Lightspeed + live MCP reads* to inspect GitOps state and explain a manual-sync delay. You used *Gitea* to change desired state and *Argo CD* to apply it, without risking the working National Parks workloads.

[cols="2,3",options="header"]
|===
| Check | Expected
| Student | `oc whoami` returns `{user}`
| Gitea | Your repository has a committed ConfigMap change
| Argo CD | `national-parks-settings` is Synced
| Kubernetes | `national-parks-gitops-info` says `Updated in Gitea`
| Boundaries | Application targets `{user}-demo`, with no broad cluster rights
| National Parks | Map and data endpoint still work
|===

== Troubleshooting

[cols="2,3",options="header"]
|===
| Symptom | What to check
| No Gitea repository | Verify tenant bootstrap migrated `openshift-5-container` after this module was merged
| Gitea rejects login | Use the student Gitea credentials, which can differ from OpenShift
| Argo CD cannot reach Gitea | Verify the HTTPS Clone URL and that the repo is public and reachable from the repo-server
| Application cannot create resources | Confirm destination namespace is yours and the Argo CD controller has namespace permissions
| App has unintended workloads | Stop; use the exact `module02-gitops` path, never repository root
| Application still OutOfSync | Select *Refresh*, inspect the diff, and use *Sync* (manual policy)
| Lightspeed cannot inspect Application CR | Use `oc get applications.argoproj.io` and the Argo CD UI; don't infer unseen resources
| Map loses park markers | Check Module 1's `parksmap-discovery` ServiceAccount and MongoDB Service port; don't fix via unrelated GitOps changes
|===

= Module 2: GitOps Onboarding & Multitenancy
:navtitle: GitOps Onboarding & Multitenancy
:page-toclevels: 2
:experimental:

In Module 1, you repaired the MongoDB Service and got the National Parks map working.
Now you will use *Gitea*, the **GA OpenShift GitOps 1.22 console plug-in** and *OpenShift Lightspeed 2.0* to manage a small part of that application's environment through Git. The OpenShift console is the main interface; standalone Argo CD is a fallback for manual synchronization only.

*Duration:* approximately 30 minutes.

[cols="1,3",options="header"]
|===
| Time | Mission
| 5 min | Check your student account and ask Lightspeed what is deployed
| 5 min | Explore your Gitea repository
| 8 min | Create an Application using the native GitOps console plug-in
| 7 min | Change Git, inspect drift in the GitOps console and synchronize
| 5 min | Check namespace isolation and application health
|===

[IMPORTANT]
====
*Your National Parks application stays running.* This lab manages **one harmless ConfigMap** associated with National Parks, not its Deployments, Secrets, Services or MongoDB settings. Your Module 1 fix will not be overwritten.

Argo CD synchronization is **manual**. Lightspeed uses MCP read tools to investigate and explain; **you** make Git changes and create/inspect the Application through the OpenShift GitOps console plug-in. No MCP write tools, cluster-admin rights or shared Git credentials are required. The separate Module 2 namespace is created by the instructor-managed GitOps tenant bootstrap, not by a student CLI command.
====

== What's new in OpenShift 5?

This lab focuses on current OpenShift 5 experiences while using established GitOps and Kubernetes concepts.

[cols="2,3",options="header"]
|===
| Feature | What you will try
| *OpenShift 5 console* | Navigate your project and inspect GitOps resources. If enabled, try the new Glass, High Contrast or Traditional console theme.
| *MCP server for Red Hat OpenShift — GA with OpenShift 5* | Ask Lightspeed 2.0 to use live read-only cluster tools. Inspect the tool evidence before accepting a diagnosis.
| *OpenShift GitOps 1.22 console plug-in — GA* | The **primary workflow** is *GitOps -> Applications* in the OpenShift console: create, inspect and monitor the Application. Use the standalone Argo CD tab only if the plug-in does not offer manual Sync.
| *GitOps 1.22 Source Hydrator and environment promotions — Technology Preview* | Learn how these relate to Kustomize and Git review. **Do not enable** Technology Preview features in this shared lab.
|===

[NOTE]
====
Argo CD, Kustomize, RBAC and manual sync are **not new to OpenShift 5**. The new elements here are how the platform exposes, secures and assists these operations. The GitOps console plug-in is **required for this version of Module 2** and must be enabled by the instructor before class. Appearance themes remain optional.

== Mission 1: Check the environment with Lightspeed (5 minutes)

. Open the Showroom *Terminal* tab. As in Module 1, authenticate as your assigned student:
+
[source,bash,subs="attributes+"]
----
oc login {openshift_api_url} -u {user} -p {password}
oc whoami
oc project {user}-demo
oc version
----
+
Expected identity: `{user}`. If you see `system:serviceaccount:...:showroom`, stop and sign in as the student. Using `-p` displays your lab password in shell history; use only this disposable workshop terminal.

. Save the Module 1 namespace, the separate GitOps target namespace, and the Application name for later:
+
[source,bash,subs="attributes+"]
----
export LAB_NAMESPACE={user}-demo
export GITOPS_NAMESPACE={user}-gitops
export ARGOCD_NAMESPACE=$LAB_NAMESPACE
export ARGOCD_APP=national-parks-settings
oc get deployments -n "$LAB_NAMESPACE" \
  -l app.kubernetes.io/part-of=national-parks-app
oc get applications.argoproj.io -n "$LAB_NAMESPACE"
oc get configmaps -n "$GITOPS_NAMESPACE"
----
+
Your National Parks workloads should be running in `{user}-demo`, while `{user}-gitops` is a separate GitOps target namespace created automatically by the instructor-managed GitOps bootstrap. It is **normal for the Applications list to be empty**: an Argo CD *instance* is already installed in `{user}-demo`, but the National Parks GitOps Application has not yet been created. The `oc version` output confirms the actual API server release; the intended workshop cluster uses OpenShift 5.

image::module02-s01-student-context.svg[S01: student terminal context and cluster version - screenshot placeholder, width=850]

. Open *OpenShift Lightspeed* -> *Troubleshooting* and paste:
+
[source,text,subs="attributes+"]
----
Use live Kubernetes tools to inspect the Argo CD instance and
Applications in namespace {user}-demo, and ConfigMaps in the
separate GitOps namespace {user}-gitops.

Tell me what GitOps resources already exist and what is missing.
Do not read Secrets or change anything.
----
+
Approve only **read** operations for your own namespace. Expand the MCP tool calls and compare the reported resource names, namespace and status with the terminal output. This is the **OpenShift 5 MCP evidence check**: a diagnosis without verifiable tool results is only a suggestion.

Lightspeed should distinguish the existing Argo CD instance from an Argo CD Application. If the MCP tool cannot read an Argo CD custom resource, use the `oc get` commands above as the source of truth; do not accept an invented resource. The MCP server normally respects Kubernetes identity and RBAC; **do not ask it to bypass permissions**.

image::module02-s02-lightspeed-mcp-inspection.svg[S02: Lightspeed read-only MCP tool evidence - screenshot placeholder, width=850]

*Explore:* Expand an MCP call and identify the **tool name**, **namespace** and **resource names** in the result. Verify these against the Terminal.

*Checkpoint 1:* You can explain the difference between the Argo CD instance and an Application, identify the cluster version and point to a read-only MCP tool result used by Lightspeed.

== Mission 2: Find your GitOps source in Gitea (5 minutes)

Each student has a separate Gitea instance and repository.

. Open Showroom's *Gitea* tab. If it is missing, open *Networking* -> *Routes* in your project and follow the Gitea Route's *Location* link.
. Sign in using your assigned student Gitea account (typically `{user}`). Gitea credentials may differ from your OpenShift login; the workshop bootstrap defaults are documented by your instructor.
. Open the pre-provisioned **`openshift-5-container`** repository in your Gitea account. The workshop has already imported it from the public GitHub source.
. Browse to:
+
[source,text]
----
content/modules/ROOT/examples/module02-gitops/
  kustomization.yaml
  national-parks-gitops-info.yaml
----
. Open `national-parks-gitops-info.yaml`. The initial message is:
+
[source,yaml]
----
data:
  message: "GitOps baseline"
----
. Select the repository's *Clone* button and copy its **HTTPS** URL. You will paste this into the OpenShift GitOps console YAML editor. Use the Gitea URL, **not** the GitHub URL. Confirm the repository is public/readable by Argo CD; never embed a password or token in the URL.

[NOTE]
====
If `openshift-5-container` or the `module02-gitops` folder is missing, ask your instructor to verify that Gitea repository provisioning completed successfully. Do not create an empty repository, run repository-import commands, or guess the GitOps source path.
====

[TIP]
====
*OpenShift GitOps 1.22 connection:* The `kustomization.yaml` file declares the desired Kubernetes resources. GitOps 1.22 adds *Source Hydrator* and environment promotions as Technology Preview capabilities; this lab uses ordinary Kustomize and a reviewed manual sync instead. Ask Lightspeed what Kustomize does if you need a quick explanation — no tools or cluster changes are needed.
====

*Try it:* Which folder contains the GitOps manifests? Confirm from Gitea's address bar.

*Checkpoint 2:* You have a real Gitea HTTPS repository URL and can see the two GitOps files.

== Mission 3: Create an Application with the GitOps console plug-in (8 minutes)

OpenShift GitOps 1.22 provides a **GA GitOps console plug-in**. You will create an Argo CD Application custom resource directly in the OpenShift 5 console. The existing Argo CD controller will reconcile it.

. Open the Showroom *OCP Console* tab, then the navigation menu -> *GitOps* -> *Applications*. If the *GitOps* menu is missing, ask your instructor to enable the plug-in before continuing.
. **Select project {user}-demo** in the OpenShift console project selector, even if the current project is {user}-gitops. The Application custom resource must live in the existing Argo CD control-plane namespace ({user}-demo). Its **destination** will be the separate {user}-gitops namespace. Creating the Application in {user}-gitops instead requires extra Applications-in-any-namespace configuration which is not part of this exercise.
. Select *Create Application*. Delete the entire default YAML template (myapp, default namespace, master revision, path ".", and automated prune). Paste this, with the attributes expanded to your student account:
+
[source,yaml,subs="attributes+"]
----
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: national-parks-settings
  namespace: "{user}-demo"
spec:
  project: default
  source:
    repoURL: "https://gitea-{user}-demo.{openshift_cluster_ingress_domain}/{user}/openshift-5-container.git"
    targetRevision: main
    path: content/modules/ROOT/examples/module02-gitops
  destination:
    server: https://kubernetes.default.svc
    namespace: "{user}-gitops"
----
+
There is intentionally **no automated sync policy**. Do not enable pruning, self-healing or force; the target namespace was already created by the instructor-managed GitOps bootstrap. The student GitOps path contains only the National Parks learning ConfigMap.

image::module02-s04-argocd-new-app.svg[S04: OpenShift GitOps plug-in Create Application YAML editor - screenshot placeholder, width=850]

. Select *Create*. Return to *GitOps -> Applications* with project {user}-demo selected and open *national-parks-settings*. In its *Details* tab, inspect the repository, destination and status. Initially it should normally be **OutOfSync** and the resource **Missing**.
. Open the *Sources* tab and confirm the Gitea source and exact module02-gitops path. Then open *Resources* (including *Graphical view*, if present). Confirm the intended resource is **one ConfigMap** named national-parks-gitops-info. If a Deployment, Secret, Route, Service, or Namespace appears, **do not sync**.
+
image::module02-s05-argocd-initial-outofsync.svg[S05: GitOps console Application OutOfSync with missing ConfigMap - screenshot placeholder, width=850]
+
*Predict before syncing:* Should the new ConfigMap already exist in the destination namespace?

[%collapsible]
====
**Answer:** No. The ConfigMap is in Git only until a reviewed manual synchronization.
====

. **Manual sync:** If the GitOps plug-in shows a *Sync* action on this Application, use it after confirming only the ConfigMap will be applied. If your installed plug-in does not expose a Sync action, use Showroom's *ArgoCD* tab **only for this step**: open national-parks-settings, select *Sync*, review the single ConfigMap, and select *Synchronize*. Do not select prune or force. Return immediately to the OCP Console.
. From *OCP Console* -> *GitOps* -> *Applications*, inspect *Details* and *Resources* again. Then verify from the Showroom Terminal:
+
[source,bash]
----
oc get applications.argoproj.io national-parks-settings \
  -n "$LAB_NAMESPACE" \
  -o jsonpath='{.status.sync.status}{" / "}{.status.health.status}{"\n"}'

oc get configmap national-parks-gitops-info \
  -n "$GITOPS_NAMESPACE" \
  -o jsonpath='{.data.message}{"\n"}'
----
+
Expected: Synced / Healthy and GitOps baseline. Brief Progressing or Unknown status is possible while the controller refreshes.

image::module02-s06-argocd-initial-synced.svg[S06: OpenShift GitOps console synced Application and one ConfigMap - screenshot placeholder, width=850]

== Mission 4: Change Git, investigate with Lightspeed, then sync (7 minutes)

. In *Gitea*, edit `content/modules/ROOT/examples/module02-gitops/national-parks-gitops-info.yaml` in your own repository. Change **only** this value:
+
[source,yaml]
----
message: "Updated in Gitea"
----
. Commit the change directly to the branch Argo CD is tracking. Do not edit any Secret or workload manifest.
+
image::module02-s08-gitea-commit.svg[S08: Gitea commit after editing ConfigMap - screenshot placeholder, width=850]
. Return to *OCP Console* -> *GitOps* -> *Applications* in project {user}-demo. Open national-parks-settings. Use *Refresh* if offered or let the controller detect the Git commit, then refresh the console page. The Application should become **OutOfSync**. The live ConfigMap still has `GitOps baseline` because automatic sync is disabled.
+
image::module02-s09-argocd-drift.svg[S09: GitOps console showing OutOfSync after Gitea commit - screenshot placeholder, width=850]
+
*Predict:* Where does the new message exist now — Git, Kubernetes or both?

[%collapsible]
====
**Answer:** Git only. The cluster still has the baseline message until a manual Sync.
====
. Before syncing, ask Lightspeed:
+
[source,text,subs="attributes+"]
----
I updated Git, but ConfigMap national-parks-gitops-info
still shows the old message in namespace {user}-gitops.

Use live Kubernetes tools to inspect the Argo CD Application
and the ConfigMap. Explain why it has not changed.

Do not read Secrets or change anything.
----
+
A useful diagnosis is that the Application uses **manual synchronization** and needs a reviewed Sync. MCP may not be able to inspect the Git commit itself; confirm Git changes in Gitea and the Application status in the OpenShift GitOps console.

image::module02-s10-lightspeed-drift.svg[S10: Lightspeed MCP diagnosis of GitOps drift - screenshot placeholder, width=850]

**Verify Lightspeed's evidence** before syncing:
+
[source,bash]
----
oc get applications.argoproj.io national-parks-settings \
  -n "$LAB_NAMESPACE" \
  -o jsonpath='{.spec.syncPolicy.automated}{" / "}{.status.sync.status}{"\n"}'

oc get configmap national-parks-gitops-info \
  -n "$GITOPS_NAMESPACE" \
  -o jsonpath='{.data.message}{"\n"}'
----
+
Expected before Sync: an empty `automated` field, `OutOfSync` and `GitOps baseline`. Check the **real results**, not only the AI explanation.

. Review the one-ConfigMap change and perform a **manual Sync** from the GitOps plug-in if the action is available. Otherwise, briefly use Showroom's *ArgoCD* tab for *Sync* -> *Synchronize* and return to the GitOps Applications page in the OCP Console. Never enable automated sync, prune or force.
. Verify the change:
+
[source,bash]
----
oc get configmap national-parks-gitops-info \
  -n "$GITOPS_NAMESPACE" \
  -o jsonpath='{.data.message}{"\n"}'
----
+
Expected: `Updated in Gitea`.

image::module02-s11-argocd-resynced.svg[S11: OpenShift GitOps console Synced after second manual sync - screenshot placeholder, width=850]

*Checkpoint 4:* You saw **Git commit -> OutOfSync -> manual Sync -> updated cluster ConfigMap**. Lightspeed helped investigate but did not modify the cluster.

== Mission 5: Confirm multitenancy and app health (5 minutes)

An Argo CD Application has a target namespace. OpenShift 5's MCP server respects Kubernetes permissions, and Kubernetes RBAC separately controls who can change resources there. This is why an AI read-only investigation cannot override tenant boundaries.

. In the Terminal, compare your rights:
+
[source,bash]
----
oc auth can-i patch deployments.apps -n "$LAB_NAMESPACE"
oc auth can-i patch deployments.apps -n openshift-config
----
+
Also check the separate GitOps destination: `oc auth can-i get configmaps -n "$GITOPS_NAMESPACE"` should be `yes` with the bootstrap-provisioned `view` RoleBinding. The second check against `openshift-config` should be `no`. If results differ, ask the instructor; actual RBAC decides.

image::module02-s12-tenant-rbac.svg[S12: namespace RBAC comparison - screenshot placeholder, width=850]

*Think:* Would NetworkPolicy change these `oc auth can-i` answers?

[%collapsible]
====
**Answer:** No. RBAC protects Kubernetes API actions; NetworkPolicy controls Pod network traffic.
====

. Inspect the namespace-scoped discovery RoleBinding and the GitOps destination:
+
[source,bash]
----
oc get rolebinding parksmap-discovery -n "$LAB_NAMESPACE" \
  -o jsonpath='{.subjects[0].name}{"\n"}'

oc get applications.argoproj.io national-parks-settings \
  -n "$LAB_NAMESPACE" \
  -o jsonpath='{.spec.destination.namespace}{"\n"}'
----
+
Expected: `parksmap-discovery` and the separate `{user}-gitops` namespace. The Application CR itself remains in `{user}-demo`.

. Check that the map still works: https://parksmap-{user}-demo.{openshift_cluster_ingress_domain}/[Open ParksMap,window=_blank] and https://national-parks-app-{user}-demo.{openshift_cluster_ingress_domain}/ws/data/all[View park data,window=_blank].

[NOTE]
====
*Multitenancy in OpenShift 5:* RBAC restricts Kubernetes API actions, NetworkPolicy restricts Pod traffic, and UserDefinedNetwork can provide additional network isolation when configured by an administrator. These are different controls; **this exercise does not create or change network policies or tenant networks**.
====

*Checkpoint 5:* You have student-scoped permissions, a manually synchronized ConfigMap, and a healthy National Parks application.

== Troubleshooting

[cols="2,3",options="header"]
|===
| Symptom | What to check
| No Gitea repository | Ask the instructor to check tenant bootstrap and Gitea repository provisioning; the workshop should already have imported `openshift-5-container`
| Gitea rejects login | Use the student Gitea credentials, which can differ from OpenShift
| GitOps menu missing | Ask the instructor to verify the gitops-plugin is enabled for the cluster; students must not install operators
| Application not visible | Select project {user}-demo (not {user}-gitops) and verify metadata.namespace
| Argo CD cannot reach Gitea | Verify the HTTPS Clone URL and that the repo is public and reachable from the repo-server
| GitOps target namespace missing | Ask the instructor to sync the privileged `bootstrap-tenant` GitOps chart; students must not create namespaces manually
| Application cannot create resources | Confirm `{user}-gitops` exists and has `argocd.argoproj.io/managed-by: {user}-demo`; check controller namespace permissions
| App has unintended workloads | Stop; use the exact `module02-gitops` path, never repository root
| Application still OutOfSync | Inspect GitOps -> Applications, check the diff and manual sync; use the ArgoCD tab only if the plug-in lacks Sync
| Lightspeed cannot inspect Application CR | Use `oc get applications.argoproj.io` and the OpenShift GitOps console; don't infer unseen resources
| Map loses park markers | Check Module 1's `parksmap-discovery` ServiceAccount and MongoDB Service port; don't fix via unrelated GitOps changes
|===

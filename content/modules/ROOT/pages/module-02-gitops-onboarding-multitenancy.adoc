= Module 2: GitOps — Deploy and Auto-Sync the National Parks Full Stack
:navtitle: GitOps — National Parks Full Stack
:page-toclevels: 2
:experimental:

In Module 1 you deployed National Parks through the OpenShift 5 console and used Lightspeed to troubleshoot MongoDB. Now deploy an *independent, complete copy* through *Gitea + the GA OpenShift GitOps console plug-in*, using Git as the source of truth.

The original application stays in *{user}-demo*. The new ParksMap frontend, Python API and MongoDB 8 stack deploys into *{user}-gitops*. You will watch OpenShift build the Python image, initialize MongoDB, load park data and automatically reconcile a Gitea commit.

*Duration:* approximately 45 minutes, after instructor preflight of storage, builds, GitOps permissions, images and student Gitea repositories.

[cols="1,3",options="header"]
|===
| Time | Mission
| 5 min | Check your student identity and the two projects
| 7 min | Explore the full-stack source in your Gitea repository
| 10 min | Create the Auto-Sync Application in the OpenShift GitOps console
| 15 min | Watch GitOps build and deploy all three application tiers
| 8 min | Commit a change, verify Auto-Sync and inspect tenant boundaries
|===

[IMPORTANT]
.Before you begin
====
* *This module deploys the full National Parks stack.* The old one-ConfigMap exercise is no longer the main lab.
* The Application CR lives in *{user}-demo* alongside your existing Argo CD instance; the deployment *destination* is *{user}-gitops*.
* The instructor-managed privileged GitOps bootstrap already creates *{user}-gitops*. Students do not create Namespaces or cluster-scoped RBAC.
* The root GitOps Kustomization in your *student Gitea repository* must include the fullstack directory. If it does not, stop and tell the instructor: an imported Gitea copy does not automatically follow upstream GitHub.
* *Auto-Sync and Self-Heal are enabled. Auto-prune is disabled.* Don't manually synchronize, delete resources, or edit GitOps-owned Deployments in the cluster.
* MongoDB credentials are generated inside the namespace by a Job. Never place passwords in Gitea, screenshots or Lightspeed prompts. MongoDB uses a 1Gi PVC and correct port 27017, unlike the deliberate Module 1 fault.
====

[cols="2,3",options="header"]

| *OpenShift 5 console* | Inspect Projects, Builds, Topology, Routes and workload status.
| *OpenShift GitOps 1.22 console plug-in (GA)* | Use *GitOps -> Applications* to create and monitor the entire deployment without the standalone Argo CD interface.

| *Lightspeed / MCP* | Ask read-only questions about actual resources and inspect tool evidence before trusting an explanation.

== Mission 2: Explore the complete GitOps source in Gitea (7 minutes)

Each student has an editable Gitea copy of the workshop source. It is *not a live GitHub mirror*, so the instructor must have synchronized the up-to-date full-stack files before this class.

. Open Showroom's *Gitea* tab. Log in with your assigned Gitea account and open its pre-provisioned *openshift-5-container* repository on branch *main*. Gitea credentials may differ from OpenShift credentials.
. Open +content/modules/ROOT/examples/module02-gitops/kustomization.yaml+. It must contain:
+
[source,yaml]
----
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization
resources:
  - fullstack
----
+
This *root directory is the main GitOps source*. If you see only national-parks-gitops-info.yaml in the resources list, the repository is stale. *Stop and notify the instructor*; do not deploy the outdated exercise.

. Open +fullstack/kustomization.yaml+ and confirm it lists all seven resources:
+
[source,text]
----
fullstack/
  kustomization.yaml
  national-parks-gitops-info.yaml
  00-mongodb-credentials.yaml
  01-mongodb.yaml
  02-nationalparks-backend.yaml
  03-parksmap-discovery.yaml
  04-parksmap-frontend.yaml
  05-park-data-bootstrap.yaml
----
+
image::module02-s03-gitea-source.svg[S03: root Kustomization and fullstack manifests in student Gitea - screenshot placeholder, width=850]

. Explore the files to identify what each one deploys:
+
[cols="2,3",options="header"]
|===
| File | Responsibility
| +00-mongodb-credentials.yaml+ | Namespace-scoped bootstrap ServiceAccount/RBAC and Job creating a MongoDB Secret without storing passwords in Git
| +01-mongodb.yaml+ | MongoDB 8 Deployment, Service, bootstrap ConfigMap and persistent volume claim
| +02-nationalparks-backend.yaml+ | Python Dockerfile BuildConfig, ImageStream, Deployment, Service and HTTPS Route
| +03-parksmap-discovery.yaml+ | Dedicated read-only ServiceAccount and RBAC for backend discovery
| +04-parksmap-frontend.yaml+ | ParksMap Deployment, Service and HTTPS Route
| +05-park-data-bootstrap.yaml+ | PostSync Job that loads park records only if the database is empty
| +national-parks-gitops-info.yaml+ | A Git-managed ConfigMap used to observe Auto-Sync later
|===
+
. Copy the repository's HTTPS *Clone* URL. Do not use the public GitHub URL as your student's GitOps source.

*Checkpoint 2:* You can identify the files for every tier and show that the root Kustomization deploys the full stack.

== Mission 3: Create the Auto-Sync Application through the console (10 minutes)

. Open *OCP Console -> GitOps -> Applications* and set the console's *Project* selector to *{user}-demo*, where the existing Argo CD controller runs. Do not put the Application CR in *{user}-gitops*; that namespace is only the destination.
. Select *Create Application*. If *national-parks-settings* already exists in *{user}-demo*, open it and edit its YAML instead of creating a duplicate. Replace the starter configuration with the *entire* YAML below:
+
[source,yaml,subs="attributes+"]
----
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: national-parks-settings
  namespace: "{user}-demo"
spec:
  project: default
  source:
    repoURL: "https://gitea-{user}-demo.{openshift_cluster_ingress_domain}/{user}/openshift-5-container.git"
    targetRevision: main
    path: content/modules/ROOT/examples/module02-gitops
  destination:
    server: https://kubernetes.default.svc
    namespace: "{user}-gitops"
  ignoreDifferences:
    - group: apps
      kind: Deployment
      name: nationalparks
      jsonPointers:
        - /spec/template/spec/containers/0/image
  syncPolicy:
    automated:
      enabled: true
      prune: false
      selfHeal: true
    syncOptions:
      - RespectIgnoreDifferences=true
    retry:
      limit: 5
      backoff:
        duration: 10s
        factor: 2
        maxDuration: 2m
----
+
The Gitea URL must match your own student repository. The root Kustomization already includes the full stack, so do not change the source path to a one-ConfigMap file. The narrow ignoreDifferences exception allows the OpenShift ImageStream trigger to replace the Python backend image without Argo CD undoing that update.

image::module02-s04-argocd-new-app.svg[S04: native console Create Application YAML including full-stack Auto-Sync - screenshot placeholder, width=850]

. Save or Create. Open *GitOps -> Applications -> national-parks-settings*. Explore *Details*, *Sources* and *Resources* (including the graphical view if available). You should see the MongoDB, backend, frontend and support objects. During startup, *OutOfSync*, *Missing* or *Progressing* can appear temporarily. Do **not** click manual Sync; automatic reconciliation is enabled.

image::module02-s05-argocd-initial-outofsync.svg[S05: initial GitOps full-stack resource tree during automated reconciliation - screenshot placeholder, width=850]

*Predict:* Where does the Application CR live, and where do its Deployments go?

[%collapsible]
====
**Answer:** The Argo CD Application lives in *{user}-demo*, but spec.destination.namespace is *{user}-gitops*, which receives all three new Deployments.
====

. Verify policy and destination using the Terminal:
+
[source,bash]
----
oc get applications.argoproj.io "$ARGOCD_APP" -n "$LAB_NAMESPACE" \
  -o jsonpath='{.spec.source.path}{"\n"}{.spec.destination.namespace}{"\n"}{.spec.syncPolicy.automated}{"\n"}'
----
+
Expected: root module02-gitops source path, {user}-gitops target, and enabled=true, prune=false, selfHeal=true.

*Checkpoint 3:* Your single GitOps Application manages the entire National Parks stack with Auto-Sync turned on.

== Mission 4: Watch GitOps deploy all three tiers (15 minutes)

GitOps uses sync-wave ordering: create credentials and namespace-scoped permissions, prepare database storage, deploy MongoDB and the Python image build, then deploy the running Python API and ParksMap. A PostSync Job loads sample data when the application is healthy.

. Watch the resource tree in *GitOps -> Applications*. In the Terminal, list the new resources:
+
[source,bash]
----
oc get jobs,pvc,buildconfigs,imagestreams -n "$GITOPS_NAMESPACE"
oc get deployments,services,routes -n "$GITOPS_NAMESPACE"
oc get secret nationalparks-mongodb-parameters -n "$GITOPS_NAMESPACE" -o name
----
+
[cols="2,3",options="header"]
|===
| Kind | Expected names
| Deployments | parksmap, nationalparks, mongodb-nationalparks
| Services | parksmap, nationalparks, mongodb-nationalparks
| HTTPS Routes | parksmap, national-parks-app
| BuildConfig / ImageStream | nationalparks
| PVC | mongodb-nationalparks-data (Bound)
| Secret | nationalparks-mongodb-parameters (name only)
| Jobs | credentials bootstrap and guarded park-data loader
|===

image::module02-s06-argocd-initial-synced.svg[S06: GitOps full-stack resources and three application tiers - screenshot placeholder, width=850]

. Open *Builds -> Builds* for project *{user}-gitops*. Inspect +nationalparks-1+ (or the latest nationalparks build). It builds the Python source from Git using its Dockerfile and pushes to the +nationalparks:latest+ ImageStreamTag. Verify:
+
[source,bash]
----
oc get builds -n "$GITOPS_NAMESPACE"
oc get imagestreamtag nationalparks:latest -n "$GITOPS_NAMESPACE"
oc get deployment nationalparks -n "$GITOPS_NAMESPACE" \
  -o jsonpath='{.spec.template.spec.containers[0].image}{"\n"}'
----
+
A short ImagePullBackOff can occur before the first image build completes. The OpenShift image trigger updates the Deployment after a successful build; the Application's RespectIgnoreDifferences setting avoids a self-heal conflict.

image::module02-s07-ocp-gitops-console.svg[S07: OpenShift Python Build Complete and ImageStreamTag - screenshot placeholder, width=850]

. Confirm the MongoDB Service uses *27017*, not the deliberately broken 27018 from Module 1. The new database uses a PVC and generated credentials. Check the Deployments:
+
[source,bash]
----
oc get pvc mongodb-nationalparks-data -n "$GITOPS_NAMESPACE"
oc get svc mongodb-nationalparks -n "$GITOPS_NAMESPACE" \
  -o jsonpath='{.spec.ports[0].port}{" -> "}{.spec.ports[0].targetPort}{"\n"}'

for workload in mongodb-nationalparks nationalparks parksmap; do
  oc rollout status "deployment/$workload" -n "$GITOPS_NAMESPACE" --timeout=180s
done
----
+
Don't inspect Secret contents or commit passwords. The backend and MongoDB both reference the namespace-local Secret.

image::module02-s08-gitea-commit.svg[S08: PVC Bound, ready MongoDB and workloads; no credential values - screenshot placeholder, width=850]

. The PostSync Job checks the collection before loading records. Find the two Route hosts and check real park data:
+
[source,bash]
----
API_HOST=$(oc get route national-parks-app -n "$GITOPS_NAMESPACE" \
  -o jsonpath='{.spec.host}')
MAP_HOST=$(oc get route parksmap -n "$GITOPS_NAMESPACE" \
  -o jsonpath='{.spec.host}')

printf 'ParksMap: https://%s\n' "$MAP_HOST"
printf 'Park data: https://%s/ws/data/all\n' "$API_HOST"

curl -fsS "https://$API_HOST/ws/data/all" | head -c 300
printf '\n'
----
+
The dataset should be nonempty and ParksMap should display park markers. The API's /ws/healthz/ check alone does *not* verify MongoDB. The /ws/data/load endpoint deletes and reloads the collection; do not call it manually as a routine health check.

image::module02-s09-argocd-drift.svg[S09: full-stack GitOps status, two Routes and loaded park data - screenshot placeholder, width=850]

*Predict:* Why is automatically calling /ws/data/load on every health check a bad idea?

[%collapsible]
====
**Answer:** That endpoint deletes and reloads all park records. The PostSync loader checks whether the collection is empty first. This dataset is disposable workshop data, not a production database.
====

*Checkpoint 4:* The build completed, the database PVC is bound, all three Deployments are ready, and your separate ParksMap Route shows parks.

== Mission 5: Commit to Gitea and prove Auto-Sync (8 minutes)

. In your *Gitea* repository edit **content/modules/ROOT/examples/module02-gitops/fullstack/national-parks-gitops-info.yaml**. Change just the message:
+
[source,yaml]
----
data:
  message: "Updated through GitOps Auto-Sync"
----
+
Commit the change to the same +main+ branch tracked by Argo CD. Don't edit the older single-ConfigMap file in the parent module02-gitops directory; the root Kustomization deploys +fullstack/+.

image::module02-s10-lightspeed-drift.svg[S10: Gitea committed change to the full-stack ConfigMap source - screenshot placeholder, width=850]

. Return to *OCP Console -> GitOps -> Applications -> national-parks-settings* in project *{user}-demo*. Wait for automatic reconciliation. It may briefly become OutOfSync, or quickly return to Synced. **Do not click Sync or modify the ConfigMap in Kubernetes.**
. Verify the value in your deployment namespace:
+
[source,bash]
----
oc get configmap national-parks-gitops-info \
  -n "$GITOPS_NAMESPACE" \
  -o jsonpath='{.data.message}{"\n"}'
----
+
Expected: +Updated through GitOps Auto-Sync+.

. Ask Lightspeed in *Troubleshooting*:
+
[source,text,subs="attributes+"]
----
Use live read-only Kubernetes tools to inspect the three
National Parks Deployments and ConfigMap national-parks-gitops-info
in {user}-gitops, and the Application national-parks-settings
in {user}-demo if the CRD is available.

Verify the live ConfigMap message, explain Auto-Sync and
Self-Heal, and identify any unavailable tools. Do not read
Secrets or change anything.
----
+
Compare the tool results with the Git commit, Application status and Terminal. Lightspeed might not have permission to read Application CRs or Git commits.

image::module02-s11-argocd-resynced.svg[S11: GitOps Synced status and updated live ConfigMap message - screenshot placeholder, width=850]

*Predict:* Do you have to click Sync after committing a change?

[%collapsible]
====
**Answer:** No. Auto-Sync detects changes in Git and reconciles them automatically. Self-Heal can correct Kubernetes drift in GitOps-owned resources, and prune=false prevents automatic removal of resources deleted from Git.
====

. Check your tenant boundary and verify Module 1 still runs:
+
[source,bash]
----
oc auth can-i get configmaps -n "$GITOPS_NAMESPACE"
oc auth can-i patch deployments.apps -n openshift-config
oc get deployments parksmap nationalparks mongodb-nationalparks -n "$GITOPS_NAMESPACE"
oc get deployments parksmap nationalparks mongodb-nationalparks -n "$LAB_NAMESPACE"
----
+
Kubernetes RBAC, not the AI prompt, controls your actual permissions. The two stacks are independent; open https://parksmap-{user}-demo.{openshift_cluster_ingress_domain}/[your original Module 1 map,window=_blank] to confirm it still works.

image::module02-s12-tenant-rbac.svg[S12: student RBAC and separate healthy application deployments - screenshot placeholder, width=850]

*Checkpoint 5:* You changed Git, not Kubernetes. Auto-Sync applied that change while the complete app and the Module 1 environment stayed intact.

== Troubleshooting

[cols="2,3",options="header"]
|===
| Symptom | Check
| GitOps menu missing | Instructor validates GA GitOps console plug-in before class
| Gitea fullstack/ missing or root Kustomization is stale | Instructor reconciles each student's imported Gitea copy; upstream GitHub merges do not update student copies automatically
| Application missing | Select project {user}-demo in the console; the destination is {user}-gitops
| Repository connection failed | Check exact student HTTPS clone URL, access and TLS trust
| Sync Forbidden | Instructor checks namespace management label and GitOps controller permissions in {user}-gitops
| Credentials bootstrap failed | Check Job, ServiceAccount, Role and RoleBinding; never print Secret values
| PVC Pending | Instructor checks default StorageClass and quotas
| Backend ImagePullBackOff | Check Python BuildConfig, Build logs, ImageStreamTag and image-trigger annotation
| Database unavailable | Verify MongoDB readiness, Secret presence and Service port 27017
| Empty park list | Check PostSync data-loader Job and MongoDB; avoid repeatedly calling /ws/data/load
| ConfigMap didn't change after commit | Verify Gitea main, Application source path, Auto-Sync settings and controller events
| Lightspeed can't read Application | Use oc get applications.argoproj.io and the GitOps console as evidence
|===
